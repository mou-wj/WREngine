# 故障与修复记录 - 2026-11-18

## GIViewer 打开工程场景时的崩溃报告与默认阶段调整

### 现象

打开 `out/pro2` 中包含一个球形静态网格的工程后，点击 View 页的 GIViewer 会崩溃。当前没有崩溃转储、异常文本或设备移除日志，故尚不能把某个具体 GPU Pass、资源状态或 Shader 错误认定为已确认根因。

### 已确认的触发路径

修改前，[EditorGIViewer](../../../src/Editor/GIViewer/Private/EditorGIViewer.cpp) 每次绘制都会调用 `GIViewerPreview::Render`；其默认模式是 `IndirectDiffuse`。该模式进入 [LumenViewerRenderer::AddPasses](../../../src/Framework/Renderer/Private/GI/LumenViewerRenderer.cpp)，先构造预览场景缓冲并初始化 Surface Cache，再更新 Direct Lighting，最后构造 Screen Probe Placement、SDF Query、Lighting Lookup、Radiance Gather 和 Integration。因而仅打开 Viewer 就会启动完整的当前 GI Viewer 路径，而不是先显示一个不执行 GI 的场景预览。此调用顺序可以从源码确认，但尚无证据证明它就是 `pro2` 崩溃的直接根因。

### 本次调整

- 将 Viewer 默认模式改为 `Scene`。Renderer 在完成预览场景绘制后直接返回，不初始化 Surface Cache、Direct Lighting 或 Screen Probe；用户选择这些阶段或点击 Build/Rebuild Surface Cache 后才运行对应流程。
- 增加 Mesh Card 场景叠加选项。Editor 将 Card 的世界投影矩形映射到当前预览图，按轴向着色并突出选中项；其为 X-ray UI 叠加，不参与深度测试。Surface Cache 图集和 Screen Probe 各阶段仍可从左侧阶段列表独立查看。
- 保持 GIViewer 自身 RenderGraph 与主渲染流程隔离，没有调整 RenderGraph、RHI 或常规 Deferred Renderer 架构。

## 后续复现与根因修复

### 崩溃证据与根因

在复测前发现两份 `Langcher.exe` 崩溃转储，Windows Error Reporting 均记录 `Renderer.dll`、异常码 `0xC0000005`，故障偏移为 `0x4B4CE`。使用该构建对应的 `Renderer.pdb` 将故障地址映射到 `DepthPyramidGenerate.obj` 中 `std::_Hash<RHITexUAVCreateInfo, ...>::_Find_last` 的实例；异常是对空对象成员地址 `0x90` 的读取。

调用链及不匹配点如下：

1. `LumenViewerRenderer::AddPasses` 为预览深度金字塔调用 `RenderGraphBuilder::CreateTexture`，创建的是 RenderGraph 内部临时纹理。
2. `AddBuildDepthPyramidPass` 调用 `GetExternalTextureViewCache` 获取该纹理的 UAV 缓存。
3. `GetExternalTextureViewCache` 只查询 `m_ExternalTextures`。临时纹理不在该外部资源表中，因此返回 `nullptr`。
4. 深度金字塔计算 Pass 执行时仍通过该空指针调用 `GetOrCreateUAV`。随后在 `TextureViewCache` 的 UAV `unordered_map::find` 中触发访问冲突。

因此，崩溃不是 GI 数据为空，而是深度金字塔 Pass 把 RenderGraph 临时资源误按外部资源查找 View Cache。该根因由匹配构建的转储、PDB 符号和 `GetExternalTextureViewCache` 实际查找逻辑相互印证。

### 修复

修改 [DepthPyramidGenerate.cpp](../../../src/Framework/Renderer/Private/DepthPyramidGenerate.cpp)：在加入 Pass 前通过 `RenderGraphBuilder::CreateTextureUAV` 为每个 mip 创建单 mip UAV 引用；执行期间使用这些 RenderGraph 管理的视图作为当前输出 mip 和前一输入 mip。原有覆盖整张金字塔的 `InDepthMipTexture` 声明保留，用于维持 Pass 对深度金字塔的 UAV 资源依赖。移除对 `GetExternalTextureViewCache` 的错误调用；没有修改 RenderGraphBuilder、RHI 或 Viewer 主渲染流程。

### 编译与 pro2 运行验证

- 编译命令：`cmake --build out/build/vscode-x64-Debug --target Renderer Langcher --config Debug -- /m:8 /v:q /clp:ErrorsOnly`，退出码为 `0`。
- 使用该构建启动 `Langcher.exe`，从 Project 菜单打开 `out/pro2`。工程加载为 3 个场景节点；进入 View 页 GIViewer 后默认显示 Scene 预览，球网格及环境背景正常绘制，没有崩溃。
- 点击 `Build Surface Cache` 后 Viewer 显示 6 张球体 Mesh Card，依次切换了 Surface Cache Base Color、World Normal、Card Coverage、Direct Lighting Atlas，以及 Screen Probe Placement、Ray Directions、Hit Ratio、Radiance、Indirect Diffuse；这些模式均正常显示并保持进程存活。最后返回 Scene / Mesh Cards，预览球体周围可见轴向 Card 矩形叠加。
- 这是该工作区 Debug 构建下对 `out/pro2` 的实际界面运行及画面检查。未对 GI 数值精度或不同显卡、后端作独立正确性验证；Screen Probe 和 Surface Cache 的画面含义仍应结合其各自算法实现理解。
