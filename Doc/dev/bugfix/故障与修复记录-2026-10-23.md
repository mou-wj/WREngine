# 故障与修复记录 - 2026-10-23

## Slate 单窗口合成与 ImGui RHI 后端

### 需求与实现步骤

1. 删除拥有原生窗口的 NativeWidget；SlateWidget 改为普通 Widget，保留既有 SceneViewport 挂载和输入转发，避免改动 Engine/Renderer 主流程。
2. Window 登记多个逻辑区域，命中测试和鼠标坐标转换在 Window 完成；补充逻辑捕获、Win32 鼠标捕获以及失焦释放，支持拖动跨越 GUI、视口和客户区边界。
3. SlateRenderer 由按 SlateWidget 创建交换链改为按 Window 管理交换链，向 UI 适配器提供 RHI 命令列表与最终目标的绘制回调。
4. ImSlateRenderer 保留每窗口 ImGuiContext，在主线程生成 ImDrawData；场景继续离屏渲染，输出 RenderTexture 加入背景 DrawList，面板和弹层在同一目标上叠加。
5. 增加模块私有的 imgui_impl_rhi.h/.cpp，复用 RenderCore 的编译、上传、资源状态和 RHI 接口；处理顶点/索引、正交投影、裁剪、字体图集、纹理 SRV、透明混合及绘制命令。
6. 移除 ImGUISlate 的原生 WGL/官方 OpenGL 图形后端路径，CMake 只纳入 ImGui 核心和项目 RHI 后端；OpenGL 原生调用继续由 OpenGLRHI worker 执行。
7. 调整 Application 帧驱动与释放顺序，窗口级统一 Draw/Present；先完成窗口提交并释放 GUI/交换链，再销毁业务拥有的控件、视口和场景资源。

未修改 Tests 的主流程、场景资源、材质参数或第三方依赖源码。SlateWidget 作为逻辑包装器继续存在，不再具有原生子窗口语义。

### 实现中发现的故障与修复

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 首次 Vulkan GUI 绘制出现 descriptor 校验错误和设备丢失 | 自有 Shader 的声明/寄存器空间未匹配 VulkanRHI 按阶段组织 descriptor set 的约定 | VS/PS 分别编译实际所需声明；Vulkan PS 使用 space1，VS 使用 space0 |

| Vulkan 目标清屏正常，但启用混合后 GUI/场景全部为黑 | VulkanColorBlendState 只设置 blendEnable，混合因子仍为 ZERO/ZERO | 在 VulkanResource.cpp 设置与现有 RHI 开关语义一致的标准 Alpha 混合因子与 ADD 运算 |

### 复查纠正：未启用的 Queue ImageLayoutManager

- 初版在 VulkanRHISwapchain::DestroySwapchain 中增加了 Graphics/Compute Queue 的 `GetImageLayoutManager()->NotifyDeletedImage` 调用。复查确认这两处是无效清理，已删除，同时删除 VulkanResource.cpp 为此新增的 VulkanBarriers.h 显式 include。
- 当前布局转换路径是上层明确提供 `RHITransitionInfo.AccessBefore/AccessAfter`，VulkanRHIApi::RHICreateTransition 将其映射为 VkImageLayout 并生成 barrier，VulkanCommandContext::EndTransitions 执行。该路径不查询 Queue ImageLayoutManager；Queue 与 CommandBuffer 间的布局状态传递仍是注释代码，没有启用第二套自动布局跟踪。
- `RenderPassManager::NotifyDeletedImage` 清理实际使用的 framebuffer 缓存，与布局跟踪不同，必须保留。原先文档把 framebuffer 与 layout 缓存一并描述为故障根因不准确，本次已纠正。
- 检查本次全部源码差异，Queue ImageLayoutManager 的新增使用仅上述两处。VulkanDevice.cpp 中原有的同类清理和未启用的管理器本体未在本次扩大清理范围。
- 删除后重新构建 Langcher、Tests 成功；实际启动 Vulkan Launcher，场景/GUI 绘制、窗口缩放及最小化恢复正常，WM_CLOSE 退出 0，子窗口数量为 0。仍有上文记录的四条既有 Shader 校验错误，没有新增布局或 framebuffer 校验错误。此次日志、截图与结果位于 `out/diagnostics/slate-layout-audit-build.log`、`out/diagnostics/slate-layout-audit-launcher/`。

### 复查纠正：交换链销毁不添加隐式 WaitIdle

- 移除本次改造在 VulkanRHISwapchain::DestroySwapchain 中增加的 Graphics/Present Queue WaitIdle。底层交换链销毁不自行引入整队列阻塞，调用方按既有生命周期保证 GPU 完成。
- 复查全部当前源码差异，没有保留任何新增的 Queue ImageLayoutManager 使用。VulkanDevice.cpp 的两处历史调用在本次改造前就存在，保持原样；没有修改 VulkanQueue、VulkanBarriers 或 VulkanSwapchain.cpp 来启用布局管理器。
- 保留 RenderPassManager 的 framebuffer 缓存失效通知，它不属于布局状态管理。
- 此次交换链复查时，SlateRHIRenderer 尚有三处窗口级 WaitIdle：ReleaseWindow、交换链 Resize 前、首版每帧提交/Present 后。这是当时的同步窗口帧实现；后续三处等待的完整整改见下节。
- 移除销毁内部等待后，Langcher、Tests 重新编译成功；实际启动 Vulkan Launcher，检查场景与 GUI、缩放、最小化恢复及正常退出，退出码为 0，子窗口数量为 0。日志仍只有上述四条既有 Shader 校验错误。证据位于 `out/diagnostics/slate-swapchain-audit-build.log` 与 `out/diagnostics/slate-swapchain-audit-launcher/`。

### 复查纠正：撤回 SlateRHIRenderer 的整队列等待

初版为方便复用 GUI 缓冲及释放资源，在窗口提交、缩放和释放处增加 WaitIdle，改变了原来的异步提交方式。这是实现取舍错误，现已移除三处调用，没有把它们移入其他函数。

整改内容：

1. SlateRenderer::Render 返回该窗口帧在 Graphics Queue 上的完成值，绘制回调可向提交添加资源的 GPU WaitInfos。绘制和 Present 正常排队后直接返回，不在帧末等待完成。
2. GUI 使用三组顶点/索引缓冲轮转，只有复用的那组 Fence 尚未完成时才等待其值。顶点/索引上传与访问转换直接录入绘制命令，不再逐帧调用同步 RenderBuffer::UploadData 或 Immediate 转换 helper。
3. 对采样纹理收集上次访问 Fence，通过 GPU 依赖及既有 RHI Transition 路径完成转换；GUI 提交后回写纹理 Tracker，避免后续场景写入忽略 GUI 读取。字体图集更新/销毁单独等待其访问完成值，沿用现有纹理上传接口。
4. Present 后增加空命令上下文作为窗口完成标记，覆盖 OpenGL worker 排队的 Present。ReleaseWindow/Resize 仅等待该窗口保存的完成值，不使用 WaitIdle；该标记本身不阻塞 CPU，代价是每窗口帧多一次队列提交。
5. OpenGLSwapchain 在 Acquire 时保留本帧索引并推进下次索引，Present 任务按值捕获本帧索引。worker 不再修改主线程正在使用的索引，消除此前依靠全队列等待掩盖的索引竞争。

未修改 RHI 公共接口、Vulkan 布局管理器、测试主流程或场景 Shader。跨队列转换沿用项目现有 TransitionResource 语义，独立 queue family 的完整所有权交接未在本轮额外验证。

验证结果：

- 实际启动 Vulkan Launcher，场景和 GUI 正常，窗口缩放、最小化恢复及正常退出完成，退出 0、原生子窗口 0。仍只有原先四条 Shader 校验错误，没有新增布局或 framebuffer 错误。
- Vulkan、D3D12 GUI 诊断均确认四象限图像、文字、半透明叠加与裁剪，点击、拖动和缩放恢复成功，退出 0，stderr 为空。

- 静态检查 SlateRHIRenderer 及 imgui_impl_rhi，未保留 WaitIdle；未增加 ImageLayoutManager 调用。

### 复查纠正：资源访问跟踪在实际提交处更新

- 前一版由 SlateRHIRenderer 提交命令，再由 ImSlateRenderer 调用 ImGuiRHIBackend::OnSubmitted 回写采样纹理的 Fence，访问状态则在录制时提前更新。虽然正常路径有执行更新，但拆散了提交与跟踪职责。
- 现在绘制回调只登记本批命令采样的纹理与使用的顶点/索引缓冲。SlateRHIRenderer 在绘制 ExecuteContext 返回后立即使用该次提交的 Fence 手动更新资源 Tracker，同时回写 SRV 或 VertexOrIndexBuffer 状态，不再借用后续窗口完成标记作为资源访问 Fence。
- 跨队列转换若单独提交，也在 sourceQueue->ExecuteContext 后立即记录该队列的转换 Fence 和 SRV 状态，随后由实际图形绘制提交更新最终访问记录。
- 删除后端 OnSubmitted 与跨帧采样纹理成员列表。EndFrame 仅管理三组帧存储的轮转，不再负责纹理或缓冲的访问 Tracker。
- 本次未新增 WaitIdle 或 ImageLayoutManager 调用。
