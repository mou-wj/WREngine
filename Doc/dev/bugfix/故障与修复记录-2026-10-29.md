# 故障与修复记录 — 2026-10-29

## 空编辑器绘制方向轴后，加入模型触发 Vulkan UBO 断言

### 现象与已确认根因

编辑器先在空场景中绘制方向轴，再加入模型，模型/阴影绘制路径使用 PositionOnlyVS 参数时触发 CPU 断言。诊断已确认实际写入 frequency=1、binding=100、offset=64、size=64，而当前 cached binding.Size 为 96。它不是模型数据必须删减或方向轴必须停用的问题。

[VulkanPipelineLayoutCache](../../../src/Framework/RHIVulkan/PublicHeader/VulkanPipelineState.h) 缓存的 VulkanPipelineLayout 不只含 VkPipelineLayout，还复制 PipelineLayoutInfo；[VulkanCommonPipelineDescriptorState::ParsePipelineLayout](../../../src/Framework/RHIVulkan/PublicHeader/VulkanPendingPipelineState.h) 使用其中 SetLayoutsByFrequency 构造资源槽映射与 PackedUniformBuffer。旧 CalculateHash 仅覆盖原生 descriptor set layouts 和有效 push constant 范围，遗漏了 CPU 参数映射和 UBO Size。

[EditorViewAxesVertexParameters](../../../src/Editor/SceneEditor/Private/EditorViewAxes.cpp) 为矩阵和两个 Float4，共 96 字节；[PositionOnlyVSParameters](../../../src/Framework/Renderer/Private/StaticMeshMaterialShader.h) 的模型/视投影矩阵需要 128 字节。两者原生 descriptor layout 相同，但 CPU 反射元数据不同。旧缓存命中方向轴先创建的 layout 后，把 96 字节 binding 上限带给模型管线，导致 SetPackedGlobalParameter 检查 `64+64 <= 96` 失败。

96 是 binding 的逻辑 Size，不应误写成 CPU Data 只分配了 96 字节：当前暂存向量按 64 字节对齐，该条目会占 128 字节。padding 恰好容纳某次写入，并不能让错误的 Shader 元数据成为正确布局；本次没有删除边界断言或把某个 Shader 人为扩成更大的常量缓冲。

### 最小修复与边界

正式实现只修改 [VulkanPipelineState.h](../../../src/Framework/RHIVulkan/PublicHeader/VulkanPipelineState.h) 的 PipelineLayoutInfo::CalculateHash：保留原生布局哈希，加入按数值排序的 Shader frequency 键、每阶段资源数量及 set/binding/count、UBO 数量及 set/binding/Size，以及 push constant 存在标记和有效范围。复用 Core 的 HashCombine。阶段 map 的排序消除 unordered_map 迭代顺序的不确定性；各条目 vector 保留其实际顺序，UBO 顺序还参与暂存区打包。

需要区分“原生 descriptor 布局可兼容”和“缓存对象内全部 CPU 数据可互换”。修复让后者参与缓存身份，没有给每个 Shader 强制创建独占缓存，也没有为模型导入增加一套参数管理机制。额外 CPU 工作只在后端管线创建的 layout 查询中进行，新增阶段排序和元数据遍历；不会在每次参数写入时排序。

方向轴的场景颜色访问已通过 Pass 参数声明给 RDG，本次不修改 RenderGraphBuilder，不增加 WaitIdle、Fence、全局保活或 ImageLayoutManager，也不改变既有模型加载/测试流程。临时断言诊断代码已撤销，原参数访问上限检查保留。缓存所有权和关闭路径继续由 VulkanDevice 及其原有缓存负责。

本次没有解决仅以 hash 作为 map 键而缺少完整相等性校验的问题，也没有给 m_Layouts 增加内部互斥；哈希碰撞和共享缓存并发的旧限制仍需单独处理。调用链、CPU 代价和生命周期详见 [Shader 编译、布局与绑定](../../key_implemetion/performance/06-shader-compilation-and-binding.md)，总体职责见 [RHIVulkan 架构](../../architecture/rhi/rhivulkan.md)。
