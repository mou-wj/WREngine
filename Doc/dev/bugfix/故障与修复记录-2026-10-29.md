# 故障与修复记录 — 2026-10-29

## 空编辑器绘制方向轴后，加入模型触发 Vulkan UBO 断言

### 现象与已确认根因

编辑器先在空场景中绘制方向轴，再加入模型，模型/阴影绘制路径使用 PositionOnlyVS 参数时触发 CPU 断言。诊断已确认实际写入 frequency=1、binding=100、offset=64、size=64，而当前 cached binding.Size 为 96。它不是模型数据必须删减或方向轴必须停用的问题。

[VulkanPipelineLayoutCache](../../../src/Framework/RHIVulkan/PublicHeader/VulkanPipelineState.h) 缓存的 VulkanPipelineLayout 不只含 VkPipelineLayout，还复制 PipelineLayoutInfo；[VulkanCommonPipelineDescriptorState::ParsePipelineLayout](../../../src/Framework/RHIVulkan/PublicHeader/VulkanPendingPipelineState.h) 使用其中 SetLayoutsByFrequency 构造资源槽映射与 PackedUniformBuffer。旧 CalculateHash 仅覆盖原生 descriptor set layouts 和有效 push constant 范围，遗漏了 CPU 参数映射和 UBO Size。

[EditorViewAxesVertexParameters](../../../src/Editor/SceneEditor/Private/EditorViewAxes.cpp) 为矩阵和两个 Float4，共 96 字节；[PositionOnlyVSParameters](../../../src/Framework/Renderer/Private/StaticMeshMaterialShader.h) 的模型/视投影矩阵需要 128 字节。两者原生 descriptor layout 相同，但 CPU 反射元数据不同。旧缓存命中方向轴先创建的 layout 后，把 96 字节 binding 上限带给模型管线，导致 SetPackedGlobalParameter 检查 `64+64 <= 96` 失败。

96 是 binding 的逻辑 Size，不应误写成 CPU Data 只分配了 96 字节：当前暂存向量按 64 字节对齐，该条目会占 128 字节。padding 恰好容纳某次写入，并不能让错误的 Shader 元数据成为正确布局；本次没有删除边界断言或把某个 Shader 人为扩成更大的常量缓冲。

### 最小修复与边界

正式实现只修改 [VulkanPipelineState.h](../../../src/Framework/RHIVulkan/PublicHeader/VulkanPipelineState.h) 的 PipelineLayoutInfo::CalculateHash：保留原生布局哈希，加入按数值排序的 Shader frequency 键、每阶段资源数量及 set/binding/count、UBO 数量及 set/binding/Size，以及 push constant 存在标记和有效范围。复用 Core 的 HashCombine。阶段 map 的排序消除 unordered_map 迭代顺序的不确定性；各条目 vector 保留其实际顺序，UBO 顺序还参与暂存区打包。

需要区分“原生 descriptor 布局可兼容”和“缓存对象内全部 CPU 数据可互换”。修复让后者参与缓存身份，没有给每个 Shader 强制创建独占缓存，也没有为模型导入增加一套参数管理机制。额外 CPU 工作只在后端管线创建的 layout 查询中进行，新增阶段排序和元数据遍历；不会在每次参数写入时排序。

方向轴的场景颜色访问已通过 Pass 参数声明给 RDG，本次不修改 RenderGraphBuilder，不增加 WaitIdle、Fence、全局保活或 ImageLayoutManager，也不改变既有模型加载/测试流程。临时断言诊断代码已撤销，原参数访问上限检查保留。缓存所有权和关闭路径继续由 VulkanDevice 及其原有缓存负责。

本次没有解决仅以 hash 作为 map 键而缺少完整相等性校验的问题，也没有给 m_Layouts 增加内部互斥；哈希碰撞和共享缓存并发的旧限制仍需单独处理。调用链、CPU 代价和生命周期详见 [Shader 编译、布局与绑定](../../key_implemetion/performance/06-shader-compilation-and-binding.md)，总体职责见 [RHIVulkan 架构](../../architecture/rhi/rhivulkan.md)。

## 场景组件位移编辑轴

2026-10-30 补充纠正：本节原先把 SceneComponent setter 的基类通知视作所有组件均已通知。实际 PrimitiveComponent 覆写的 MarkRenderStateDirty 是占位代码，位移时仅置场景 dirty 不足以刷新代理；当时前后图像变化可能来自位移工具本身，不能单独证明模型已移动。后续缩放检查排除工具变化后暴露此缺口，已在 EditorScene 写回后沿原 NotifyComponentChanged 接口显式通知，并补充关闭工具的模型独立对照。详见 [2026-10-30 记录](故障与修复记录-2026-10-30.md)。本节保留当时的验证范围，不将其推广为该缺口已在 10-29 被覆盖。

SceneEditor 增加 [EditorTranslationGizmo](../../../src/Editor/SceneEditor/PublicHeader/EditorTranslationGizmo.h)，借用 SceneComponent，通过 SceneViewDrawExtension 向同一 RDG 添加颜色叠加。X 红、Y 蓝、Z 绿，支持三条单轴及 XY/XZ/YZ 原点四边形平移；可拖动句柄悬停/按住为黄色。Node Properties 的 Position 行增加 Move 开关，NodeEditor 通过宿主回调启停，仍不依赖 SceneEditor。没有实现旋转、缩放、吸附或撤销。

Drag 只返回世界位置候选，EditorScene 沿原具体队列完成点等待后调用 SetWorldLocation，并在下次绘制前 Flush。当时误以为 setter 已自动通知所有组件；2026-10-30 已补充显式 NotifyComponentChanged，使静态网格代理实际刷新。单轴/平面只改选定世界分量，父节点旋转和非均匀负缩放通过既有父矩阵逆转换回 local。目标切换、删除和工程清空前解除借用，失焦/松开/resize/相机切换和聚焦结束拖动。接口及职责见 [Editor 架构](../../architecture/app/editor.md)，公式和退化处理见 [位移算法](../../key_implemetion/algorithm/03-transforms-frustum-and-depth.md)，提交与生命周期见 [UI 工程实现](../../key_implemetion/performance/08-ui-rendering-and-window-lifetime.md)。

### 开发中定位的问题

- 首次启用报 `Editor translation shaders are unavailable`。日志进一步记录 PS 编译时缺少 `/Generated/ShaderParameters/EditorTranslationVertexParameters.sf`。全局 Shader 使用 unordered_map 遍历，PS 可先于 VS 编译；当前 include 展开器在条件宏预处理前展开文本，所以 PS 也需要该头已注册。修复是在 PS 编译环境中用现有 ShaderCompiler 接口显式生成/注册 VS 头，保留 PS 自己的附件元数据，没有修改公共编译器或依赖偶然遍历顺序。失败记录为忽略目录 `translation-gizmo.stdout.log`、`translation-gizmo.stderr.log`。
- 独立诊断程序直接调用 viewport.Resize，首次遗漏旧目标的完成点，产生 framebuffer/image/view 仍在使用时销毁的 Validation 错误。诊断改为先完成实际读回再 resize，沿真实窗口已有的完成要求；未为产品增加 WaitIdle 或隐式保活。初次结果保留于 `translation-gizmo-registered.*`。
- 诊断尾部同一帧 AddMesh 后立即 ClearObjects 暴露现有 Scene pending Add/Remove 缺口：AddPrimitive 只排队，RemovePrimitive 查找已注册 map 而忽略尚未 Flush 的 Add；ClearObjects 随后 Flush 注册对象，却释放其组件 owner，留下悬空引用。`translation-gizmo-final.*` 保留该失败。真实编辑器常规投放包含绘制/Flush；独立工具验证改为每次添加先完成实际绘制/读回，再清空。本轮没有修改 Scene.cpp 或把此缺口宣称为已修复；它仍属于需单独处理的场景生命周期限制。
- 完整 UI 驱动最初在帧结束后读取已清空的 ImGui FontBaked，后改用 DrawList 的字体和字号取得烘焙字形；重开工程后还需先进入 sphere 包目录再拖网格，不能继续假设当前位置是导入后目录。两项均只调整忽略目录驱动，未给正式代码增加测试接口；失败阶段日志保存在 `translation-editor-stages.*` 和 `translation-editor-font.*`。
