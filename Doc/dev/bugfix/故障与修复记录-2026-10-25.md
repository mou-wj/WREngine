## 材质编辑器数据基础调整

本次保留 MaterialAsset 拥有 Material、组件按需独占 MaterialInstance 的设计，未增加 MaterialInstanceAsset、独立管理模块或 RHI 后端改动。具体接口见 [材质架构](../../architecture/material.md)。

### 已确认问题与修复

| 问题 | 原因 | 调整 |
| --- | --- | --- |
| 参数设置成功却不一定参与绘制 | 参数定义、加载与 Shader 参数构建分别维护；部分字段没有绑定 | 统一内置 Surface 参数声明、类型校验、默认值与构建入口；尚未实现的 Pass 能力明确说明 |
| 参数键不适合作为稳定的数据契约 | 使用 typeid 名称拼接字符串 | 使用名称、语义、显式参数类型组成键，复用 Common HashCombine |
| 纹理实例覆盖可能失去资源所有者 | 只保存 RenderTexture 借用指针 | 参数和快照保留 TextureAsset 引用，实际资源仍由资产拥有 |
| 编辑后旧渲染代理可能失效 | unique_ptr 缓存重建，批次保存裸指针；Renderer 回读业务对象 | 发布不可变共享快照，批次与在途帧持有引用，并从快照获取渲染状态 |
| 材质模型不能真实控制绘制 | Forward / Deferred 读取模型后强制设置 Lit | 使用 MaterialResource 提供的模型，Unlit 使用材质参数 |
| ShaderMap 缺失排列时成功路径返回值不确定 | 两个 CompileShader 缓存后没有 return | 返回实际 Shader，并保留查询、过滤、编译失败原因 |
| Normal 纹理标记与 Shader 不一致 | CPU 使用 bit1，Shader 定义 Normal 为 bit2 | 统一五类纹理 mask；新增绑定测试检查 bit2 |
| 默认纹理没有确定内容 | 每次构建创建未初始化的临时 EmptyTexture | 初始化资产拥有的白纹理和平面法线纹理，重复注册和复用 |
| 同名资源替换可能复用错误 RDG 对象 | 外部注册最终调用按名字缓存的 CreateTexture | 材质注册名包含资产路径与实际 RHI 地址，区分同名不同资源 |

动态值更新只改变参数版本；双面状态更新影响光栅状态；ShadingModel 更新影响编译配置。编译资源继续复用全局 ShaderMap，并在缓存键中区分平台。RenderModule 在图执行更新 Fence 后保留材质依赖，正常帧只查询完成值，关闭时等待记录的具体 Fence，没有新增 WaitIdle。

### 实现与验证过程中遇到的问题

- 新参数头在标准库头之前包含 HashHelper，触发当前 MSVC 14.34 的内部错误；调整包含顺序后编译正常，没有修改 Common 的哈希算法。
- 含 unique_ptr 参数集合的导出类需要明确禁止复制；为 Material、MaterialInstance 和 MaterialRenderProxy 显式删除复制操作。
- 参数类型改为资产引用后，同步迁移 JSON 加载和 Shader 参数构建；旧 StaticMeshRenderTest 只更新一处状态读取，测试主流程未改变。
- 新 Shader 编译测试初次使用了 LocalVertexFactory 不支持的全零特征，且异常退出时没有先释放测试全局纹理。改为声明当前支持的 UV+Normal 特征，并让测试在异常路径也执行资源清理。修正后 Vulkan、DirectX12 均通过。

## 材质职责与提交生命周期修正

本节记录后续复查的修正，替代上节初版的“资产拥有默认纹理”和“RenderModule 保留在途材质帧”方案。

其中关于 RDG 共享 Pass 所有权及通用 retained 列表的实现后来已按用户要求撤回；这些条目和生命周期测试只记录当时版本，当前实现以文末“撤回 RDG 与 retained 扩展”为准。

| 复查问题 | 原因 | 修正 |
| --- | --- | --- |
| 默认纹理依附于 Engine 材质绑定实现 | 将公共渲染资源包装成私有 TextureAsset 全局变量 | 移到 RenderCore/RenderResource，统一初始化并上传白色、平面法线像素；材质只引用，实际用户纹理仍由资产拥有 |
| 剔除只能由双面决定为 None 或 Back | 材质没有 Front/None/Back 配置，也缺少 Pass 覆盖入口 | MaterialRenderState 保存 CullMode；ResolveCullMode 按显式 Pass 覆盖、双面 None、材质策略的顺序解析；根 JSON 字段 cullMode 保存配置，旧文件默认 Back |
| 编译资源混入光栅状态及重复查询缓存 | MaterialResource 同时负责渲染配置与编译缓存 | 光栅状态进入按值保存的 MaterialRenderState；Resource 仅保留编译输入、Shader 引用和错误；全局 ShaderMap 负责缓存 |
| MaterialFrame 依靠渲染目标推测保活时机 | 将提交生命周期放进材质帧结构 | 删除 MaterialFrame、快照帧列表及相关纹理枚举接口；RenderCore 按实际队列提交 Fence 保留 Pass 闭包捕获的所有者 |
| 删除帧列表后需要明确 Pass 闭包的所有者 | RDG 使用 new 创建 Pass，却只 clear 裸指针列表，原本会泄漏闭包与捕获对象 | Builder 显式拥有创建的 Pass，提交后将共享引用保留到实际提交 Fence；未提交图可直接释放 |
| 关闭时不能先销毁池和 ShaderMap | 在途提交可能仍引用这些资源 | ShutdownModule 在清理池之前等待已记录的具体提交 Fence；公共资源释放时再清理剩余保活引用；没有新增 WaitIdle |

已有资源 Tracker 的 UpdateLastAccessFence 和显式转换仍在原提交位置，通用保活接口不替代这些职责。本轮未修改 RHI 或三个后端。

三角形像素 Shader 当前直接返回 float4(1,1,0,1)，没有消费顶点颜色，所以纯黄色符合当前测试输入，并非本轮发现的颜色故障。光追 Shader 自行用 DispatchRaysIndex 生成射线方向，画面方向应与其射线定义核对，不能直接用光栅测试的朝向判断；本轮两个光追后端的画面一致。

### 已定位的视口差异

RHIRenderTriangleTest 在 BeginRenderPass 之前显式 SetViewport/SetScissor(512×512)，但本机实际客户区为 496×473，DirectX12 交换链日志也打印该尺寸。

- VulkanGraphicContext::BeginRenderPass 不覆盖已设置的视口，因此继续使用 512×512。
- DirectX12GraphicContext::BeginRenderPass 使用 RenderArea 重写 viewport 和 scissor，覆盖先前显式设置。
- OpenGLGraphicContext::BeginRenderPass 使用 RenderArea 重写 viewport，并按 RenderTargets.Dimensions 重写 scissor。

因此同一份 RHI 调用顺序产生了不同的三角形大小和位置。这是已确认的跨后端动态状态语义不一致，不能把三个后端都“画出了三角形”记为一致性通过。本轮仅检查、记录，没有用修改测试视口来掩盖差异。后续修复应明确 BeginRenderPass 与显式 viewport/scissor 的优先级，并覆盖“先设置状态再开始 Pass”的调用顺序。

### 方向差异与未完成项

OpenGL 的参数测试已目视确认上下翻转。当前 OpenGL 的 BlitTexture 和 Swapchain::Present 都按原生正向矩形调用 glBlitFramebuffer；坐标契约、上传、计算纹理访问和最终呈现各阶段仍需进一步定位，不能仅凭画面把根因归到某一个调用。OpenGL 光追在不支持报错后的退出问题也未在本轮修复。

## 撤回 RDG 与 retained 扩展

用户要求取消 RenderGraphBuilder 的修改，并移除非必要的 retained 逻辑。复查确认，RetainRenderObjectUntilFence 的生产调用方只有先前新增的 RDG Pass 保活代码，除此之外只有对应的新测试；它不是默认纹理迁移、材质状态拆分或剔除策略调整的必要前提。此前将材质调整扩大成通用 RDG 生命周期改造，范围不合适。

本次调整：

- 移除 m_PassOwners、队列提交后保留 Pass 的逻辑及 Execute 前回收调用；RenderGraphBuilder.h/.cpp 对照 HEAD 的内容完全一致。
- 删除 RenderResource 中的 RetainedRenderObject、全局容器、互斥量和 Retain/Collect 接口；RenderModule 中新增的关闭等待也删除，RenderModule.cpp 恢复为 HEAD 内容。
- 删除专门测试上述已撤销机制的 RenderSubmissionLifetimeTest，原有三角形、Shader 参数、光追测试流程不变。
- 保留 GlobalWhiteTexture / GlobalFlatNormalTexture 及公共资源初始化、释放逻辑；保留材质编译与光栅状态分离、剔除策略和参数绑定调整。
- 更新架构文档，删除“RDG 共享拥有 Pass 并按 Fence 保活”的现行设计描述。源码中已无 retained 接口、容器或调用。

原有资源访问 Fence 更新及显式状态转换没有改动。CPU shared_ptr 不能等价于 GPU 完成；本次没有声明现有生命周期在任意并发编辑场景下都安全，也没有另加一个回收层来替代已撤销方案。原 RDG Pass 裸指针释放问题恢复为原有状态，作为独立问题保留，不在本次继续修改。
