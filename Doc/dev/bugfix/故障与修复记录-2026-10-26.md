## 实例缓冲失效与 Vulkan 顶点流缓存

现象：新 Editor 首帧后崩溃，Validation 报 Invalid VkBuffer，调试名 InstanceIdBuffer；Windows 事件记录异常位于 VkLayer_khronos_validation.dll。独立动态场景测试也在材质编辑重建资源后暴露同类问题。

源码证据与修正分为两层：

1. Editor 初次每帧 FlushPendingUpdates，现有 Scene 刷新会重新生成 GPU 实例块。改为只有实际变更才刷新；旧缓冲被替换前，依据视口输出纹理实际提交/采样写入的 Tracker 等待具体队列 Fence。移除组件时在销毁拥有者前先消费移除命令。没有新增 WaitIdle、retained 容器或 RDG 回收改造。
2. 即使完成旧提交，VulkanPendingGfxState::Reset 仍保留 m_PendingStreams；后续新 command buffer 的 Draw 可能把已合法销毁的旧句柄再次绑定。Reset 现清空所有 pending streams。这是原生状态缓存错误，不能通过无限保留旧资源来替代修复。

修复后，动态场景测试完成重复绘制、参数编辑、网格复制/移除和关闭，日志没有再出现 Invalid VkBuffer 或 UNASSIGNED-Threading-Info。正常帧没有新增等待，实际编辑仍有一次具体完成点等待成本；没有宣称它是无阻塞多版本场景系统。

## 变换编辑不进入渲染代理

原 StaticMeshProxy 只保存局部平移；Scene::NotifyComponentChanged 对 Primitive 只置 GPU dirty，没有更新代理缓存矩阵/Bounds。修正为读取完整 GetComponentTransform（逻辑 const 读取），变更通知将新代理放进现有 keyed AddPrimitive 命令，在 Flush 时替换旧代理。

独立测试比较代理矩阵与含旋转/非均匀缩放的组件矩阵，相等；复制保留母材质资产、创建独立实例并复制实际覆盖。没有顺带修复既有 Shader 非均匀缩放法线或距离场尺度问题。

## 文本输入缺失

原输入链只有有限 KeyEvent，未转发 WM_CHAR。为使目录/保存路径和属性输入可用，Win32 表面改为明确的 Unicode 窗口/消息分派，UTF-16 字符经 OnTextInput 到 ImGuiIO；补齐编辑键、修饰键和常用剪贴板/撤销组合键的映射。保留平台层与 ImGui 的边界。完整 IME 组合窗口定位、中文字体与高 DPI 行为仍需后续验证。

## 编辑器区域边界拖动与系统光标

原界面布局固定指定几何，ImPanelWidget 每帧 SetNextWindowSize 且 NoResize，因此只解除 NoResize 并不能保留用户尺寸。现由 EditorLayout 保存两侧宽度/底部高度的比例，三条 ImSplitterWidget 负责命中和拖动回调；两侧分隔条为左右拉伸，底部横条为上下拉伸，均保留 6 像素操作区。区域有最小尺寸，ribbon 高度保持固定。该实现没有引入 Docking、原生子窗口或新的资产/渲染管理器。

同时补齐 ImGui 光标到 SlateCore/Win32 的转换。平台层用系统共享光标及 HTCLIENT 的 WM_SETCURSOR，UI 不直接调用 Windows API。主动更新只作用于本窗口客户区/捕获期间，系统外边框仍保留默认缩放样式。

实现时需要处理的边界：

- ImGui 默认最小窗口尺寸会把 6 像素 splitter 放大：控件局部覆盖 WindowMinSize、Padding、Border，保证操作区域不盖住相邻面板。
- 视口几何改变会替换 RenderTexture，必须在上一窗口使用完成且本帧纹理引用生成前执行。三个 splitter 先于场景和 UI 面板绘制，仅实际比例改变时执行 UpdateLayout，等待之前 Render 已返回的窗口完成 marker，保留原有 Access/Fence 更新位置。
- ReleaseWindow 不仅等待，还删除 swapchain 状态，不适合内部连续拖动。最终实现单独等待该窗口已有完成值，不调用 ReleaseWindow、不反复创建主交换链，也没有新增 WaitIdle、保活列表或命令提交。
- 拖动从激活时的鼠标坐标开始计算增量；松开/失焦沿用 ImGui 输入状态清理，尺寸下限不继续触发重排。比例在当前会话保留，未写入磁盘配置。

## 资源浏览器文件系统树与卡片视图

根据用户提供的 UE 内容浏览器与 Godot 文件系统截图，将 AssetEditor 改为左侧 res:// 文件系统树、右侧当前目录卡片视图。提供目录/文件层级、目录展开、树与卡片选择联动、前进/后退/上级/路径栏、两处筛选、资源类型过滤、卡片尺寸和内部可拖分隔边界。默认底部区域改为可用高度的 35%，保留完整卡片行和底部操作条，用户仍可拖主界面边界修改。

公共 ImGridWidget 增加类型图标，默认色球保持原材质库行为；ImPropertyControls::Text 补充 hint 复用现有动态字符串缓冲。界面只保存路径/目录元数据，双击或 Open 才进入原 LoadSync 和网格回调，材质/纹理选择与赋值流程保留。未新增模块、RHI/Renderer 逻辑、资源保活管理器或测试流程修改。

已处理的错误边界：读取失败时仍保证 TreePop/EndChild 配对；读取网格元数据放在进入网格 child 前，防止异常跳过结束调用。选择已删除文件失败时清除路径，避免双击误开旧选择。刷新与原地资产重载分开，内容根之外的导航明确拒绝，符号链接条目跳过。

## 工程菜单、空工作区与独立节点属性

此前 Editor 自动加入演示球体、浏览引擎资源并常驻材质侧栏，不符合工程编辑工作区的使用方式。当前实现改为：菜单栏位于 ribbon 上方；Project 提供 New/Open/Close；未打开工程或新建工程时节点列表为空、资源区为空、视口只有原有预览背景，材质编辑器隐藏。右侧固定区域改为独立 NodeEditor DLL 的节点属性面板，局部 TRS 与网格信息通过同步选择回调取得，不反向依赖 Editor/SceneEditor。材质资源用户单击后打开同一 ImGuiContext 的浮动编辑窗口，关闭后不会自行重开。此前章节中的常驻材质栏/演示场景描述是各阶段的历史记录，当前行为以本节及 [Editor 架构](../../architecture/app/editor.md) 为准。

工程目录创建 RenderingLearn.project.json 和 Content；不覆盖已有工程或非空 Content。打开先验证描述与内容根再清理旧工作区；非法打开保留当前工程。Core::GetProjectDir 继续指向引擎内置资源，不更改全局路径。Close 清空场景、面板、筛选/历史、待导入和待投放路径，再清理 AssetManager 驻留引用。工程目前不序列化场景布局，重新打开只恢复内容浏览，场景仍为空。

关键实施边界与处理：

- 菜单回调不能直接释放工程资源：本帧 CPU DrawList 可能已经保存旧纹理指针。只记录动作/路径，下一 TickFrame 在 Draw 前执行，并等待窗口已有 completion marker；场景移除命令在组件销毁前 Flush。复用显式等待与访问记录，没有新增 WaitIdle、retained 容器、RHI/Shader/RenderGraph 改动。
- 资源文件导入不等于实例化。AssetEditor 的 Import/桌面投递按帧复制到独占新包目录，glTF 和材质 JSON 本地依赖复制后改为相对路径；失败只清理本次新包。导入后不加载网格、不生成节点。GLB 外部依赖因本实现不重写二进制 chunk 而明确拒绝，避免导入后丢依赖。
- 资源卡片只传含结束符的 UTF-8 路径。视口只在该拖动活动期间生成透明逻辑接收区域；接受后延迟到下一 TickFrame，在当前工程内验证路径并经既有 AssetManager/EditorScene 创建静态网格。放置位置为世界原点，尚非射线求交定位。
- 材质程序选中与用户打开分开：Import/Refresh 不弹窗，用户点击材质才打开；SetContentRoot 清除旧工程的面板强引用和排队路径，避免旧导入投向新工程。
- 工程名字来自 Windows filesystem::path，若用本地窄字符串写 JSON，中文名字可能不符合 UTF-8；改用现有 MaterialLibrary::PathText 转换后写入与显示。这只处理工程元数据和菜单文本，不宣称 Engine 窄路径加载及中文字体已经完整支持。
