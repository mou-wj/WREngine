# 故障与修复记录 — 2026-11-04

## 工程基础层快照的 IBL 初始化完成点

前置实现见 [11 月 3 日工程快照记录](故障与修复记录-2026-11-03.md#改为只保存纹理基础层)。普通纹理只保存基础层并重建 Mip，天空光只保存环境输入并重新预计算 IBL；文件格式、所有权和调用链见 [工程快照实现](../../key_implemetion/performance/10-project-snapshots.md)。

### 现象与根因

工程用例已退出 0，场景和天空光保存重开像素也一致，但 project-base-mips-ui.stderr.log 仍有 7 条 VUID-vkDestroyImageView-imageView-01026：VkImageView 在对应 VkDescriptorSet 的提交尚未完成时销毁。因此不能把进程退出和像素通过说成资源生命周期验证通过。

[当时的 SkyLightAsset::Create（现已迁入环境光管理器 Build）](../../../src/Framework/Engine/Private/EnvironmentLightResourceManager.cpp) 复用 PreComputeIBL 后立即返回。PreComputeIBL 已提交 Compute，并在输入及两张输出记录同一个实际 Fence；返回并不代表 GPU 完成。ProjectArchive 加载随后还会校验父关系、数值等数据，拒绝恢复时会释放已创建但未注册的资产，独立加载对象也可以很快释放。新恢复路径没有等待初始化完成，六个 specular 视图和一个 diffuse 视图可能仍被计算使用。

### 修复

在 SkyLightAsset::Create 完成预计算提交后、返回资产前，读取 specular 输出 Tracker 的实际 Fence 并 WaitValue。它与 diffuse 属于同一提交，因此只需等待一次。等待属于同步恢复资产的初始化阶段，不移入通用析构，不增加 WaitIdle、延迟回收容器或后端特例；后续渲染使用仍遵循已有显式完成点。普通纹理重建和只保存基础层的逻辑保持不变。

## 环境光计算产物改由 Engine 管理

### 职责和交互调整

环境输入可作为 TextureAsset，但 diffuse/specular IBL 是计算产物，定义为 SkyLightAsset 会混淆文件资产和运行时生成结果。按新的职责划分，删除 SkyLightAsset.h/.cpp，在 Engine 增加 EnvironmentLightResourceManager.h/.cpp，管理构建、按输入对象身份复用、应用及显式释放。EnvironmentLightResource 是同一头中的非资产结果对象，只有输入及两张生成纹理。SkyLightComponent 持有使用引用，贴图 Getter 读取该结果，不再暴露裸 IBL Setter；AssetManager 不再包含或创建天空光资产。

新建天空光使用管理器创建的中性灰默认环境，原 Application 同步改为这一行为，不自动加载示例 HDR 图片。默认输入为管理器自己的 1×1 UNorm 像素，无 TextureAsset 或文件依赖；工程 environment=0 表示默认，默认输入及生成输出均不写盘。用户输入仍只保存基础层，加载由管理器重新预计算；已有基础层快照格式保持兼容。

天空光 EnvironmentTexture 通过通用 ComponentProperty 追加 TextureAsset 引用类型。资源面板单击图片即可加载并选中；NodeEditor 用宿主回调获取该选择，Use selected texture 调用管理器构建、应用，Reset 恢复默认。没有单独的天空光属性面板或功能模块相互依赖。输入会被显式纳入工程内容，因此应用后及源文件不再存在的重开场景中，Project data 都显示输入 TextureAsset。属性赋值失败显示错误并保留旧绑定。

构建继续等待实际 IBL 初始化 Fence，再发布结果，不增加 WaitIdle。普通场景删除、清空及关闭在原完成点之后 ReleaseUnused；加载失败在局部恢复节点销毁后清理未引用结果；Engine 关闭时清管理器拥有引用。原 Application 还补齐遗漏的 SkyLightComponent 删除，避免使用引用泄漏。实际调用链、线程边界、缓存和 GPU 生命周期见 [环境光工程实现](../../key_implemetion/performance/05-assets-materials-and-instance-data.md#环境光计算产物管理)，总体边界见 [Engine 架构](../../architecture/engine.md)。
