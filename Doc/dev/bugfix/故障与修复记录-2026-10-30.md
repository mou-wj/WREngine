# 故障与修复记录 — 2026-10-30

## 缩放与旋转编辑工具

新增两个实现文件：[EditorScaleGizmo.cpp](../../../src/Editor/SceneEditor/Private/EditorScaleGizmo.cpp) 和 [EditorRotationGizmo.cpp](../../../src/Editor/SceneEditor/Private/EditorRotationGizmo.cpp)。类声明、公用投影和颜色绘制复用既有 EditorTranslationGizmo.h/.cpp，Shader 继续使用原 TranslationGizmo.sf。没有新增工具管理器、Shader、GPU 几何缓冲或独立窗口，也没有修改 RHI / RenderCore / Renderer。

Scale 行开关显示局部 X/Y/Z 轴、端点圆点，以及各轴世界长度 50% 处中点之间的连线。轴和端点可选，连接线作参照；沿按下时固定的轴屏幕方向向外拖动指数放大、向内拖动缩小，垂直于该方向的位移不改倍率。操作保留选中缩放分量的符号与其他 TRS，绝对值限制在 [0.01,10000]，零值、非有限值和范围外分量不提供可拖高亮。Rotate 行开关显示三个局部轴法向圆环，沿圆拖动连续累计有符号角，侧视圆环回退到按下位置的投影切线。扇形和起止径向线显示角度；扇形最多显示一圈，实际旋转继续累积。两工具与 Move 互斥，使用 X 红、Y 蓝、Z 绿，悬停/拖动为黄。

LocalRotation 按 `R_start * R_axis(delta)` 组合，LocalScale 仅改选中分量。可视方向由父子纯旋转矩阵积确定，忽略负/非均匀缩放，保持正交圆环；这属于局部 TRS 编辑，不宣称父非均匀缩放下的世界刚体操作。缩放工具现采用 55px 单位参考长度，各轴长度随对应 LocalScale 的绝对值变化，负值不反转轴方向；本日后续调整见末节。公式、极点和多圈反馈边界见 [算法细节](../../key_implemetion/algorithm/03-transforms-frustum-and-depth.md)，所有权和提交见 [UI 实现](../../key_implemetion/performance/08-ui-rendering-and-window-lifetime.md)，模块接线见 [Editor 架构](../../architecture/app/editor.md)。

## 变换属性已变化，模型绘制仍使用旧代理

首轮两个独立入口均失败：组件 LocalScale 和 UI 数值已达到 exp(0.4) / 1.35，但实际模型图像与缩放前逐字节相同。当时缩放工具使用 90px 参考长度，几何不跟随 LocalScale，因此该检查排除了工具自身变化的干扰；这描述的是本日后续轴长调整之前的版本。失败保存在忽略目录 `out/diagnostics/scale-rotation.*` 与 `scale-rotation-ui.*`。

根因是 [PrimitiveComponent.cpp](../../../src/Framework/Engine/Private/PrimitiveComponent.cpp) 覆写的 MarkRenderStateDirty 仍为占位实现；虽然 SceneComponent 基类方法会 NotifyComponentChanged，setter 经虚调用后没有执行这个基类行为。[StaticMeshProxy](../../../src/Framework/Engine/Private/StaticMeshProxy.cpp) 在构造时复制完整 ComponentTransform，后续 Draw/Flush 只有 dirty 标记时无法替换旧快照。之前位移检查的图像差异可能只来自移动的工具，不能证明模型代理刷新。

修复限定在 EditorScene 的三个工具写回位置：沿原视口 Tracker 的具体队列完成点 WaitForLastDraw，调用对应 setter，然后显式 NotifyComponentChanged 并置 m_bSceneDirty；下次 Draw 沿原 FlushPendingUpdates 更新代理。该通知方式与节点属性面板的已有 onChanged 流程一致，不修改 Engine 的组件接口或后端同步。增加了关闭工具后模型独立读回对照，防止仅凭圆环、扇形或坐标轴变化误判模型更新成功。

## 其他实现与审阅问题

- Core::MakeRotationMatrix 采用 Rz(Z)·Ry(Y)·Rx(X)，但 GetEulerRotation 当前返回值 Y/Z 顺序相反。新旋转文件按相同 ZYX 约定显式提取，比较等价 Euler 并处理极点，不修改公共数学接口；公共函数的原有限制仍需另行修复。
- Scale 数值输入与 Scale 按钮同名，必须用不同 ImGui ID。属性行复用本地绘制函数，在工具按钮周围 PushID(label)，同时保留窄栏输入和按钮同排。
- 侧视圆环的投影极值点可能没有有效切线。命中和 BeginDrag 共用 DragReference 检查，无法建立稳定参考时不高亮或激活，避免视觉反馈与可操作性不一致。
- 共用颜色 Pass 将三角形复制到 Builder arena，参数指针 vector 也由 arena 构造和析构，闭包仅捕获稳定指针；不把额外堆 vector 复制到存在原有释放缺口的 Pass 闭包。没有为此引入保活容器或修改 RenderGraphBuilder。旋转最多 452 个三角形/Draw，有明确 CPU/驱动成本，尚未批处理。

## 后续调整：缩放端点距离与轴长反馈

用户反馈缩放单位点离原点较远，且拖动缩放时轴长不随比例变化。调整仅位于 EditorScaleGizmo.cpp 的 `BuildGeometry`：单位参考尺度从 90px 改为 55px，端点改为 `origin + basisAxis * unitLength * abs(LocalScale[axis])`。因而单位缩放时工具更紧凑，放大或缩小时相应轴与三点连线一起变化；负缩放继续保持原颜色方向，不沿负轴翻转。55px 是像平面平行方向的参考长度，实际投影仍受轴朝向和透视影响，不等于每条轴都固定投影为该像素数。

绘制与 HitTest 共用这份几何，命中随端点一起更新；拖动倍率仍以按下时的缩放和鼠标位置计算，不让不断移动的端点反馈到倍率。未修改位移/旋转工具或缩放写回与代理通知流程。

保留现有 12px 轴投影可操作下限和投影裁剪限制，没有新增显示长度钳制。极小缩放或正对视线的轴可能无法命中，极大缩放可能使端点被近远面或视口裁剪；此时可用属性数值恢复。此后已完成该轴长调整版本的独立工具/GPU 和真实 Editor UI 验证，动态端点随缩放变化，绘制及命中同步，正常退出；产物为忽略目录中的 `scale-axis-length*` 与 `scale-axis-length-ui*` 日志。当时仍使用固定屏幕 Y 倍率与端点之间连线，未覆盖下一节用户反馈的方向一致性与中点连线要求。

## 后续修复：缩放方向与鼠标相反、连线位置不符

用户手动操作发现默认视角下两条轴的缩放方向与鼠标相反，并要求辅助三角形连接各轴的一半位置。旧 `Drag` 固定使用 `dy=pressY-currentY`，向屏幕上方总是放大；默认视角 X/Z 轴的向外投影朝下，因此沿这两条轴向外拖动时 dy 为负，反而缩小。这不是缩放属性符号或渲染代理错误，而是固定屏幕 Y 输入与各轴实际屏幕方向不一致。此前上下拖动测试按旧公式验收，没有覆盖沿每根轴向外/向内的操作预期。

最小修复是在 `BeginDrag` 保存 `normalize(screenEnd-screenOrigin)`，`Drag` 改用 `distance=dot(mouse-pressMouse, frozenDirection)` 计算指数倍率。向外增大绝对值、向内减小，垂直轴线投影的位移不改倍率；方向固定在按下时，轴长随缩放更新也不会反馈到拖动计算。保留原有 55px 单位参考、绝对缩放控制轴长、负值符号、上下限和 EditorScene 的显式代理通知流程。

连接线改用 `Project(origin + axisOffset*0.5)` 得到的三个世界中点投影，端点圆点仍在各轴完整长度处。没有采用屏幕原点与端点的算术平均，避免透视下连线位置偏离世界轴长 50%；辅助线继续只显示、不提供新句柄。仅调整既有缩放实现与其按下方向字段，不改位移/旋转、RHI 或渲染图框架。

旧版本已由独立 C++ 入口复现：沿默认 X 轴向外拖动 30px，屏幕方向约 (0.872,0.489)，实际缩放却从 1 降到 0.863488，检查退出 1。产物为忽略目录 `scale-direction-before.stdout.log` / `.stderr.log`。修复后的检查仍保留“每根轴向外必须增大绝对值”的验收条件。
