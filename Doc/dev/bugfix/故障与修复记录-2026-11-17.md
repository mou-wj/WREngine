# 故障与修复记录 - 2026-11-17

## Surface Cache Material 第一阶段

### 范围与最终数据流

新增 Renderer/Private/GI 的 [SurfaceCacheMaterial](../../../src/Framework/Renderer/Private/GI/SurfaceCacheMaterial.h) 及捕获、Lookup、SDF 查询和 Debug Shader，新增独立 [SurfaceCacheMaterialTest](../../../src/Tests/SurfaceCacheMaterialTest.cpp)。既有代码仅补齐 ShaderParameter.h 中 UInt2/UInt4 的类型特化；没有修改 RHI 后端、RenderGraph、StaticMesh、Material Helper、Global SDF 或主渲染编排。

流程为：场景/显式实例快照 → 六向 Card → 原 LocalVertexFactory/材质参数的正交捕获 → 持久 BaseColor/Normal/PBR Atlas → 局部 SDF Ray Hit 保留最近实例 → Card 覆盖核验 → 材质查询与 Debug。Global SDF 不保存 Instance ID，因此这一阶段使用现有对象级 SDF Atlas，并非给全局场添加 ID 或改写原 GI。

算法与限制见 [Surface Card](../../key_implemetion/algorithm/16-surface-cache-material.md)，所有权、显式完成点和调用见 [工程实现](../../key_implemetion/performance/12-surface-cache-material.md)。本阶段没有直接/间接光照缓存、反射、Radiosity、Screen Probe 或 Radiance Cache。

### 1. 整数向量元数据缺失与生成头引用

初版 global Shader 编译失败，诊断预处理内容中 SurfaceCacheQuery.Control 和 QueryResult.Status 被生成为 float，根参数引用的 Cache 字段也没有出现在当前生成头正文。Capture 又报 `/Generated/ShaderParameters/SurfaceCacheCapturePSParameters.sf` 不存在。

原因分别是：ShaderParameterTypeInfo 缺少 UInt2/UInt4 特化，不能由 CPU 成员类型自动得到正确整数反射；StructReference 会注册另一个生成头但不自动展开为当前头的字段；现有 include 预处理在条件编译前展开文件，VS/PS 放在一个文件的两个条件分支仍会尝试读取另一阶段尚未注册的头。

修正为沿已有 UInt3 类型信息补齐 UInt2/UInt4，按既有约定显式 include Cache 参数头，并将新捕获 VS/PS 拆开，仅共享必要 varying 和视图参数。没有更改编译器预处理、元数据生成或绑定架构。最终 GPU Card/Instance/Query/Result 数据及 ID 的三后端读回正确。

### 2. OpenGL std140 排布与跨阶段常量冲突

最初 OpenGL global Shader 翻译报 `Buffer block cannot be expressed as any of std430, std140, scalar...`。新 Debug 参数的 uint 后紧跟 uint2，在 DX 布局中该向量可从 offset 4 开始，但不能按当前 GLSL 块布局表达。将 OutputSize 放在前面、Mode 放在后面，使新参数的布局同时适合两种约束；未修改其他参数或编译选项。

后续 Atlas 中 UV 和材质色正确，但无贴图法线出现 `(0.707107,0.707107,0)`、`(0.707107,0,0.707107)`，-X Card 甚至无有效覆盖。导出实际编译 GLSL 后确认：VS 的 SurfaceCacheCaptureVSParameters 在 binding=1 保存 NormalToWorld，PS 的独立 CaptureNormal 块也在 binding=1。后端使用同一个 UBO 槽，PS 写方向分量覆盖了 VS 矩阵开头，导致顶点法线和 Coverage 错误。

新捕获流程改为两阶段共用同一份 SurfaceCacheCaptureViewParameters（矩阵、方向和手性），PS 参数引用并复制 VS 的同一数据；这本来就是同一 Card 视图的数据，不再拆成两个无关常量块。该函数不再有冲突，但不能据此声称任意不同的阶段常量块已被后端自动隔离。更一般的绑定问题记入 [优化项](../optimize/优化点-2026-11-17.md)，Shader 专题原先“已按阶段隔离”的概述也已按实际代码校正。

### 3. DirectX12 阶段签名和 Atlas 动态状态顺序

DirectX12 首次创建新图形 PSO 报 `Create graphics PSO failed (HRESULT 0x80070057)`。初版 VS 返回含 SV_Position 的外层结构，PS 直接接内部 VF varying；改为两阶段共用完整 SurfaceCacheCaptureVaryings 后 PSO 创建正常。此次未捕获 D3D 调试层的详细寄存器消息，不虚构寄存器编号。

随后 DirectX12/OpenGL 中查询均返回“有命中、无覆盖”，Atlas Tile 边框断言也失败，Vulkan 同输入通过。原因是新 Capture 在 BeginRenderPass 之前设置 Tile viewport/scissor，而这两个后端会在 BeginRenderPass 内按完整附件重新设置动态状态，实际绘制覆盖了其他 Tile。将新 Pass 的 Tile 动态状态设置移到 BeginRenderPass 之后，三后端均通过；没有改后端行为或放松边框断言。

### 4. 不必要的片元 demotion 能力依赖

初版 Vulkan 数值测试通过，但 PS 的 clip 产生 DemoteToHelperInvocation capability，设备未启用相应 feature，出现 pCode-08740，不能记为无校验错误通过。

材质缓存已有独立 Coverage，因此改为让最近几何层正常写深度，背向 Card 的层只将 Coverage 写零。Lookup 拒绝该样点，既不误用背向材质，也不穿过该层伪造更深层覆盖；不需要 discard/demotion，也未为这项材质缓存扩展设备 feature。最终专项没有上述校验错误。

### 最终编译与专项验证

Debug 的 Tests 和 Langcher 完整构建成功，仍有既有 C4251/C4244/TEXT 等警告。命令为 `Tests.exe -test=SurfaceCacheMaterialTest -rhi=Vulkan`，另选 DirectX12/OpenGL；原测试文件和 main 没有改动。

三个后端均完成两帧、每帧 41 个查询，18 张 Card 的中心覆盖及无效边框断言通过；新测试使用真实 DistanceFieldManager 生成两个盒网格的局部 SDF，并创建三个实例，包括资源共享、旋转、镜像和非均匀变换。验证内容包含多 Section 材质槽、非中心 UV 渐变、法线贴图、Metallic/Roughness、18 个直接命中、18 个带 ID 的 SDF 射线、3 个无 ID 的最近命中、miss 和不被有效 Card 覆盖的内部点。第二帧只注册已有 Atlas，不重复捕获。查询迭代统计也区分直接命中与实际 SDF 采样。

Atlas 和查询 Debug 都有真实 GPU 图像输出与数值读回；实际查看了材质 Atlas 和查询色块图，来源测试文件在构建目录生成 SurfaceCacheDebug-*.ppm / SurfaceCacheQueries-*.ppm。材质与 UV 合成色误差小于 0.075（RGB 向量长度）、法线点积大于 0.995、PBR 标量误差小于 0.005，全部 Instance/Card/状态断言通过。它不是任意复杂模型的严格覆盖或 SDF 精度证明。

原 VirtualGeometryMaterialResolveTest 与 VirtualGeometryStreamingTest 在 Vulkan/DirectX12/OpenGL 的六项回归均退出 0，无测试或校验错误。忽略目录日志为 surface-cache-final-build.log、surface-cache-final-tests.log、surface-cache-regression-summary.log。失败迭代保留在 surface-cache-summary-1～6.log；早期 OpenGL 失败断言后有未正常退出、被诊断脚本 90 秒超时终止的轮次，最终版本三后端约 3～5 秒自然退出，不将早期终止写成正常退出验证。

主运行目录启动 `Langcher.exe -app=Editor`，日志确认 Scene/Assets/Material 面板初始化及 `First scene and GUI frame submitted`，进程保持响应并留作手动检查，未验证正常关闭。日志为忽略目录 surface-cache-launcher.stdout.log / .stderr.log；仍有既有 GlobalDiffuseLightMapInitCS、GlobalDiffuseLightMapDiffuseCS、HZBOcclusionTestCS、ScreenSpaceReflectionDepthPyramidCS 编译失败及 Vulkan pCode-08737，不能记为整套应用无错误通过。新增 Surface Cache global/capture Shader 在三后端专项中没有这些错误。
