# 故障与修复记录 - 2026-11-14

## Virtual Geometry 独立场景构图入口

新增 VirtualGeomtryRender.h/.cpp，将可见 StaticMeshProxy 筛选、现有实例 ID 查询、变换和材质快照整理，与 Visibility Raster、Material Resolve 的编排合并到 AddVirtualGeometryRender。入口使用调用方的 SceneDepth 与 GBuffer A/B/C，需要额外的 SceneView 提供相机和视口，不新增 Process 类或全局批次缓存。Raster 新重载直接使用传入的深度附件，原 width/height 接口继续保持自行创建深度的行为。使用条件见 [Renderer 使用约定](../../specification/renderer_spec.md)。RenderModule、传统延迟绘制及公共材质 Helper 均未修改。

新测试早期有两处自身问题。首先使用了实际不存在的 UnmapReadTexture，编译失败；核对 RHIApi 后改用现有 Unmap。中间版本漏掉释放，虽然 Vulkan 完成像素校验，但设备销毁报告仍有映射的 StagingBuffer，并异常退出。最终在完成读取后统一 Unmap，再判断像素结果，最终 Vulkan 正常退出且无校验错误。其次，初版查询临时 RDGTexture 的 GetTracker，Fence 为零，导致提前失败。现有 Builder 对瞬态纹理更新的是瞬态 RenderTexture 的 Tracker，对外部纹理则将记录同步到外部资源。测试改为与场景调用方相同的外部附件，并核对实际外部深度的 Tracker，没有修改 Builder 或取消非零 Fence 断言。

最终 VirtualGeometryRenderTest 对 19×13 空场景的 Vulkan、DirectX12 分别退出 0，用时 2.61、0.61 秒，标准错误为空。检查了输出深度与输入是同一 RDG 对象、外部深度 Fence 非零、Visibility 全部为无效双 UINT32_MAX、深度为 1，以及 GBuffer A/B/C 每个通道为零。汇总为 out/diagnostics/virtual-geometry-render-final-results.json，逐项日志使用相同前缀。

OpenGL 同一测试未通过。MapReadTexture 调用 GetOpenGLTextureFormat，D32_Float 没有对应分支，返回默认 GL_RGBA；对深度图调用 glGetTextureSubImage 产生 GL_INVALID_OPERATION（1282），随后深度读回断言失败。测试打印失败后 20 秒仍未退出，脚本主动终止。这说明当前 OpenGL 深度读回存在已定位的格式映射缺口，不能仅凭这次错误读回断言深度绘制本身错误。本次保持断言和后端实现原样，没有扩大修复范围。

原 VirtualGeometryRasterTest 复测在 Vulkan、DirectX12、OpenGL 均退出 0，用时 3.47、2.02、2.30 秒，标准错误为空，日志和结果为 out/diagnostics/virtual-geometry-render-results.json 及对应测试/后端前缀。该测试继续验证自建深度的非空网格、多实例和 ID 映射，不替代新入口非空 Scene 的验证。

主目录 Tests、Langcher 编译退出 0，最终构建日志为 out/diagnostics/virtual-geometry-render-unmap-build.log。目前只验证新入口的空场景，非空 Scene 的收集和材质求值未通过本轮端到端验证；公共材质 Helper 回退后的 Compute 采样问题仍保留，具体错误见 [此前记录](故障与修复记录-2026-11-13.md)。配置新增源码后，入口已编入 Renderer，但未接入应用的传统渲染主流程。

主目录 Langcher.exe -app=Editor 隐藏启动检查确认首个场景和 GUI 帧提交，进程保持可响应，检查后主动终止本次启动的 PID 47000。仍有既有四个全局 Shader 编译失败及 pCode-08737 校验错误，未验证正常关闭或完整场景画面，也不能用该传统路径首帧验证新入口的非空场景。日志为 out/diagnostics/virtual-geometry-render-launcher.stdout.log 及同前缀 stderr.log。
