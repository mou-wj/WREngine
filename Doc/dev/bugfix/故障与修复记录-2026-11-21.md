# 故障与修复记录 - 2026-11-21

## 世界探针缓存验证

### Shader 参数与环境占位

世界网格原生坐标最初使用 `Core::Int4`。ShaderParameter 没有该类型的对应特化，生成的 `LevelOrigin0/1` 为标量 float。DXC 在读取 `.xyz` 时报告 swizzle 越界。改用已有 ShaderParameter 支持的 `Core::Int3`，直接传入三维坐标。屏幕探针此前还引用了物体材质 Shader 生成的 `GBufferTextureParameters`，独立专项不会注册该元数据。Placement 和 Integration 现在只包含实际使用的 `GBufferInputParameters`。 [世界参数](../../../src/Framework/Renderer/Private/GI/WorldRadianceCache.h) · [屏幕探针](../../../shaders/GI/ScreenProbePlacement.sf)

无环境光时，瞬态占位 Cube 在 Vulkan 下实际得到 2D ImageView，触发 `VUID-vkCmdDispatch-viewType-07752`。GI 预览与回归用例现在注册既有的 `GlobalEmptyCubeTexture`。天空分支依旧由 `bHasEnvironment` 控制。 [环境参数](../../../src/Framework/Renderer/Private/SceneShaderParameters.cpp)

### 两面墙测试中的方向候选

最初图集已经有有效几何方向，但屏幕缓存只命中天空，SDF 步数没有下降。读回显示部分射线附近的四个方向像素中有低权重天空像素，导致整个几何候选被拒绝。方向过滤以最近样本为基准，只混合与其同类的有效方向，并要求这些方向贡献至少 0.8 的原始权重。测试输入也改为显式单位矩阵后再设置投影逆矩阵分量，避免把填充值构造误作单位矩阵。 [方向查询实现](../../../shaders/GI/WorldRadianceLookup.sf)

### Debug 与 GPU 读回

Debug 的 `Tests`、`Editor` 和 `Langcher` 构建成功。运行 `Tests.exe -test=WorldRadianceCacheTest -rhi=<后端>`，对比相同的 128 条屏幕射线。近处红墙直接受光，12 个世界单位外的白墙接收跨面 Radiosity。下表“复用”指预算为 0 且相机跨细层一格后，返回相同层级和 Radiance 的屏幕射线。

| 后端 | 缓存命中 | 移动后复用 | 完整追踪 SDF 步数 | 缓存路径 SDF 步数 | 缓存红色反弹 R / G |
| --- | ---: | ---: | ---: | ---: | --- |
| Vulkan | 22 | 22 | 57 | 50 | 0.289354 / 0.0160721 |
| DirectX 12 | 55 | 55 | 57 | 41 | 0.288137 / 0.0160076 |
| OpenGL | 55 | 55 | 57 | 41 | 0.285594 / 0.0158663 |

近墙对照验证了该组射线仍返回同一 SDF 光照，灯光撤除并失效后回到全长追踪且不返回旧亮度。`SurfaceCacheRadiosityTest` 和 `SurfaceCacheDirectLightingTest` 同样在三个后端通过并正常退出。表中仅统计屏幕追踪的步进，刷新世界探针与插值开销需独立测量。 [GPU 专项源码](../../../src/Tests/SurfaceCacheRadiosityTest.cpp)

### Launcher 界面复验

通过隔离构建的 `Langcher.exe -app=Editor` 打开 `out/pro2`。`World Probes / Radiance Atlas` 显示两个层级的方向纹理和无效方向色块。`Screen Probes / World Cache Hits` 显示球体边缘的青色和紫色命中，关闭 `Use world cache` 后同一区域变为灰色。关闭 GIViewer 后主场景继续绘制，隔离版编辑器随后通过窗口退出，未产生新的崩溃转储。Vulkan Launcher 启动日志仍包含历史 Shader 模块诊断，本次预览日志中未见新的世界探针 Shader 或 Cube 视图校验错误。 [既有诊断](故障与修复记录-2026-11-20.md#giviewer-界面复验)
