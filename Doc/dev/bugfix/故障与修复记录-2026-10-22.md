# 故障与修复记录 — 2026-10-22

## Asset 重构导致 Launcher 材质外观变化

### 现象

Asset 所有权重构后，Launcher 中原本具有明显环境反射与高光的球体变成较粗糙的非金属外观。此前仅验证了程序运行和退出，未充分验证画面与原有版本一致。

### 根因

旧 `MaterialAsset::Load` 只读取 `parameters`，而 DefaultWhite 文件使用 `scalarParameters/vectorParameters`，因此旧版本实际未设置 Metallic/Roughness。渲染参数构建使用默认金属度 0.8、粗糙度 0.2。

重构同时接通分组 JSON 解析后，文件中的金属度 0.0、粗糙度 0.5 开始生效。结构调整因此带来了未获要求的场景外观变化；此前将这项解析修正直接纳入重构，没有迁移默认资产的实际视觉参数。

另一个验证问题：上次最终留存的 `asset-launcher-before/after/running.png` 都是初始化白屏，不能作为视觉一致性的证据；固定等待时间和正常退出码不足以证明已经完成场景绘制。

### 修复

- 保留正确的分组材质参数解析，将 DefaultWhite 的显式材质数据迁移为原先实际生效的值：metallic 0.8、roughness 0.2。不在加载器或 Renderer 中硬编码场景兼容分支。
- AssetOwnershipTest 使用独立生成的测试材质，继续验证粗糙度 0.5 的分组解析、组件参数隔离及生命周期，避免与场景默认资产的美术参数绑定。
- Launcher 验证改为等待非白屏场景连续出现，再使用窗口内容抓取，避免其他桌面窗口遮挡截图。

### 验证与证据

- Langcher、Tests 的 MSVC Debug 构建通过；`Tests.exe -test=AssetOwnershipTest` 返回 0、stderr 为空。
- 分别运行保留的重构前 `out/build/x64-Debug/Langcher.exe` 与修复后的 `out/build/vscode-x64-Debug/Langcher.exe`，约 23.7 秒和 19.8 秒取得已绘制窗口；均通过 WM_CLOSE 正常退出 0。
- 人工检查两张截图，均显示原有金属球、环境反射及高光。窗口截图中场景区域 `(8,31)-(530,592)` 的 RGB 平均绝对差和最大通道差均为 0；此结果限定于本次启动场景、相机及窗口捕获，不代表所有场景回归已覆盖。

- isLoaded 直接变为 IsLoaded 会与成员函数重名，最终按私有布尔成员规则统一为 m_bLoaded，并更新所有成员引用。
- 按访问权限改名时，工具遗漏了 InstanceDataMgr.inl 中 5 处依赖类型的友元成员引用；MSVC 实例化模板时报 C2039。已将管理器锁和实例 ID 数据的访问同步为 m_Mutex、m_InstanceIds、m_bInstanceIdsDirty，保持原有锁和更新流程。
- 编码修复与命名修改保留独立检查点及补丁，便于用户确认后分别审查、提交；当前没有执行 Git 提交或推送。
