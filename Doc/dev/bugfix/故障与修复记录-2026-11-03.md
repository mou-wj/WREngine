## MeshViewer 单网格检查模块

新增独立 MeshViewer DLL，由 Editor 组装；View ribbon 的 Mesh viewer 打开同一 ImGuiContext 内的浮窗，可从当前场景选择网格节点、查看 LOD/顶点属性/区域信息。离屏预览用独立 Phong 定向光 Shader，不改变源材质或场景对象；线框和法线使用 LineList。模块及生命周期见 [编辑器架构](../../architecture/app/editor.md#meshviewer-单网格检查)、[资源时序](../../key_implemetion/performance/08-ui-rendering-and-window-lifetime.md#meshviewer-预览与检查)，几何与光照见 [预览算法](../../key_implemetion/algorithm/05-pbr-ibl-and-sampling.md#meshviewer-的-phong-预览)。

实现期间处理的问题：

1. 公共头使用 Core::Int2，必须直接包含 Math.hpp，不能依赖 ImWidget 的间接 include。首轮编译失败后已修正。
2. 法线 pass 的管线关闭深度写入，但当前 RHI RenderPass 不支持只读深度附件。最初把 RDG bWriteDepth 设为 false，产生 READ_ONLY 与 ATTACHMENT 初始布局不一致的 VUID-00900；现保持 RDG 保守深度附件声明，仅在 pipeline 关闭深度写入。最终真实界面用例没有该条校验错误，未修改后端或 ImageLayoutManager。
3. 视觉复核发现“线框/面像素不同”的诊断漏掉了线框为空。实际根因是公共 RHIPipelineStateCache::HashGraphicsPipelineDesc 漏算 PrimitiveTopology；独立原生管线诊断记录 requested=1、returned=3（LineList 请求返回 TriangleList）。补上一项 HashCombine 后三后端五种拓扑均返回正确描述，相同请求仍复用。没有通过改变线框的其他状态规避缓存；诊断补上必须绘出亮边像素的断言，并保留原差异检查。
4. Regions 表头由 ImGui 滚动子窗口绘制，诊断原来只查询父窗口，出现假失败；改为同时检查对应子窗口，未改业务 UI 或降低显示要求。

### 实现过程中确认的问题

- RHITexture 的 mip 尺寸直接右移，使 2D 纹理 Depth=1 在高 mip 变为 0。读回出现 VUID-vkCmdCopyImageToBuffer-srcImage-07980、imageExtent-06661，像素比对失败。公共尺寸计算改为各维至少 1；没有修改 Vulkan 后端。
- RenderTexture 的上传/读回按局部范围更新 Tracker，屏障却没有携带对应 mip/slice；上传登记还混用了 All 通配符，精确键查询返回 Unknown。改为传递实际子资源范围，上传登记具体 mip/layer/plane。工程保存读回后在原队列恢复原访问状态并记录真实 Fence，避免保存后继续采样到 TransferSrc 布局。读回前先等待该纹理已有提交，避免 OpenGL 同步任务越过未执行命令；没有 WaitIdle 或 ImageLayoutManager。
- OpenGL 上传、读回原来固定绑定 GL_TEXTURE_2D，Cube 出现 GL 1282；数组纹理分配还错误使用 Depth 而非 ArraySize。按既有 worker/context 模型改用 DSA 子资源上传/读回，数组分配改用层数，并设置和恢复紧密像素行对齐。转换仍使用已有 Utils，不在主线程调用 GL。
- 多次恢复网格后，距离场 Atlas 的 8 个槽位耗尽。原构建忽略 Allocate=false，继续上传零尺寸区域；网格资产析构也没有归还槽位。StaticMeshAsset 现在在原资源所有权和完成点之后归还局部槽，构建失败回滚并报错。Atlas 容量和新旧场景同时准备的限制保留，没有增加常驻缓存或扩容。
- 诊断驱动曾在 Loop::Shutdown 后仍持有一个纹理参数的 shared_ptr，导致已打印关闭日志但进程最终返回 0xC0000005。修正驱动自身的资源释放顺序后，最终进程退出码为 0。关闭日志不能代替退出码。
- 后续复查发现进程退出 0 仍有 VUID-vkDestroyDevice-device-05137：12 条纹理/视图未释放报告。定位到 AddPass 使用 new，而 Builder 析构仅 clear 指针列表，按值捕获的 MeshBatch 保留 MaterialRenderProxy 和旧工程纹理。只补齐逐项 delete Pass；CPU 录制已由 WaitAll 完成，没有增加 GPU 等待或保活容器。独立 weak_ptr 反例 project-pass-lifetime-before 退出 1，修复后的三后端用例均验证捕获已释放；完整工程用例的 05137 数量为 0。

SkyLightComponent 改为持有 SkyLightAsset，后者拥有环境输入 TextureAsset 和派生输出。工程只保存环境输入基础层；加载复用 PreComputeIBL 重新生成 diffuse 和六层 specular，不能用普通 Mip 平均代替。Editor 和原 Application 的创建入口均绑定该资产；移除仅为保存 IBL 增加的 TransferSrc/TransferDest 用途。只提供裸 IBL 输出而没有输入的天空光保存时明确报错。
