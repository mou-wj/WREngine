## 文件对话框缺少新建目录和跨盘导航

现象：ImFileDialogWidget 只有初始位置、预设位置和上级导航。工程目录选择时不能就地创建目录，也没有可发现的盘符切换入口。

处理限定在该控件的既有头文件与实现：左侧 Drives 列出可访问盘符，打开/Refresh 时同步检查并缓存；文件列表右键和工具栏增加 New folder，模态输入名称，成功后自动进入新目录。取消不创建，名称不允许成为相对/绝对路径，重名目录或文件不覆盖，失败保留当前位置并显示错误。名称与路径显示统一为控件内 UTF-8，复用已有 ImPropertyControls 文本输入。目录、单文件、多文件模式继续使用原确认回调，没有改动上层工程流程、RHI 或测试主流程。

已执行验证：

- Visual Studio 2022 x64 Debug 的 Langcher 目标构建成功，相关宿主 DLL 随头文件变更重新编译。
- 忽略目录 out/diagnostics/editor-smoke/file-dialog-main.cpp 链接实际 ImGuiSlate.dll，用本应用 ImGui 输入在文件列表空白区域打开右键菜单/创建模态，并通过标准控件激活检查目录落盘和确认回调。重名目录、既有文件、`../escape`、非法名称拒绝；Cancel 不产生目录；中文目录创建及原 Select Folder 回调返回正确路径；Directory 和 SingleFile 模式均检查通过。行项目上的右键命中按同一子窗口规则实现，未单独逐行验收。
- 两个实际可访问盘符的导航检查通过，驱动退出 0，日志为 out/diagnostics/file-dialog-smoke.stdout.log，标记 FILE_DIALOG_CONTEXT_CREATE_DUPLICATE_CANCEL_UTF8_AND_DRIVES_OK drives=2。
- 真正 Langcher.exe 默认 Editor 启动并提交首帧，观察 25 秒后外部停止；该进程未由窗口正常关闭。结果记录在 out/diagnostics/editor-actual-result.json，不将有限启动观察替代目录交互检查。

盘符列表只包含当前可访问的盘符，未就绪介质不列出；网络文件系统检查可能同步阻塞。没有据此宣称权限错误、任意网络盘、全部操作系统或完整中文字体显示都已验证。Computer Use native pipe 连接失败（os error 2），未完成真实桌面鼠标/截图验收；控件内部输入检查不能替代 OS 桌面验证。已有 Shader/SPIR-V 报错属于此前记录的渲染限制。

## 空工程仍显示节点属性窗口

现象：空工程右侧仍显示 Node Properties 标题和 Select a scene node 提示。原因是判断放在 DrawContent 内，父类 ImPanelWidget 已经执行 ImGui::Begin 创建窗口。

首轮修正只涉及 NodeEditor 的既有头文件与实现：Draw 在无选中组件时直接返回，HitTest 同样拒绝命中；有选择时沿用原面板绘制及 TRS 编辑。该轮没有修改布局，仍保留了空白右栏，不满足整个区域应被回收的要求；后续按下节调整，当前行为以整栏折叠为准。

VS 2022 x64 Debug Langcher 构建通过。忽略目录 out/diagnostics/editor-smoke/project-main.cpp 使用实际 Loop、Editor 和功能 DLL：检查初始/新建工程/仅导入网格时无 Node Properties；投放网格并自动选中后窗口存在；通过原 Scene 面板 Remove 删除最后一个节点后窗口消失；再次投放恢复；关闭/重新打开工程后无节点窗口。实际球体像素差异仍为 84,610，完整驱动正常 Loop::Shutdown，退出 0，日志为 node-visibility.stdout.log / node-visibility.stderr.log。没有为此改动 src/Tests 主流程。

本次检查使用应用内部 ImGui 输入及窗口活动状态，不等价于真实桌面鼠标验收；任意空白点击取消选择未新增交互，本次仅调整已有选择状态对应的面板显示。既有 Shader/SPIR-V 报错仍存在。当前操作规则见 [Editor 架构](../../architecture/app/editor.md)，执行边界见 [UI 核心实现](../../key_implemetion/performance/08-ui-rendering-and-window-lifetime.md)。

## 无节点时右侧仍保留空白布局列

确认原因：EditorLayout 始终扣除右栏宽度及右分隔条，NodeEditor 不生成窗口只影响绘制，不能回收布局空间。

在既有 EditorApplication.cpp 内修正：初始 NodePanel 为 Collapsed；TickFrame 在 Draw 前把场景选择映射到节点面板的 Visible/Collapsed，仅状态改变时调用原 UpdateLayout。布局折叠时令右栏宽度、右分隔条及右栏最小宽度为零，隐藏该分隔条，视口延伸到客户区右边缘。右栏比例保持原值，重新选中节点后恢复。没有新增公共接口、选择缓存或资源管理器；视口尺寸变化仍使用已有窗口完成 marker，不增加 WaitIdle、命令提交或 RHI 修改。

构建与验证：

- 默认构建目录的编译完成，但链接因正在运行的 Launcher 占用 Editor.dll 而失败（LNK1168）。未结束用户进程，也未覆盖其正在使用的 DLL；改在 out/build/editor-layout-validation 中配置、完整构建 VS 2022 x64 Debug Langcher，退出 0。
- 实际 ProjectEditorSmoke 重新链接独立目录中的真实 DLL 并调用实际 Loop：初始、新建、仅导入、删除最后节点、关闭和重新打开工程均检查右属性窗口/右分隔条不存在、视口右边缘等于客户区右边缘、RenderTexture 宽度对应显示宽度。选中节点时恢复属性栏及分隔条，再次折叠/展开保留右栏宽度，完整流程正常 Shutdown，退出 0。
- 此次 1540×845 客户区内，空工程/删除/关闭后的视口目标为 1314×456，展开属性栏时为 873×456。已读回并查看两种尺寸的实际场景图片：空工程为背景，选中网格时存在球体；关闭后的扩展视口像素与初始背景完全相同。尺寸/投影同时变化，驱动的跨尺寸像素差异不作为独立模型正确性证明。
