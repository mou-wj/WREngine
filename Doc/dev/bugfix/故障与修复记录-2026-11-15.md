# 故障与修复记录 - 2026-11-15

## Virtual Geometry GPU Cluster Culling / LOD Selection

### 目标与实际范围

将已完成的 CPU Group DAG 选择迁移到 Compute，并复用原 Visibility Raster、属性恢复和 GBuffer 链路。用户随后允许补充 RHI 间接绘制，因此正常渲染直接消费 GPU 参数，不依赖每帧读回后再由 CPU 决定 Draw 列表。

独立入口为 [VirtualGeometryGPUSelection](../../../src/Framework/Renderer/VirtualGeometry/VirtualGeometryGPUSelection.cpp)，公式、合法 Cut 证明、布局、剔除及复杂度见 [LOD 专题](../../key_implemetion/algorithm/13-virtual-geometry-lod-selection.md)。RHI 命令沿现有 CommandList/Context 分派到三个后端，所有权、工作线程和屏障见 [RHI 完成点专题](../../key_implemetion/performance/02-rhi-queues-and-sync.md#索引间接绘制与-gpu-生成参数)。Engine Build 结构、VertexFactory、传统主场景延迟流程和材质求值逻辑没有重做。

GPU 场景构图入口与 Viewer 已开启此流程。低层 VirtualGeometryInstance::bGPUSelection 默认 false，保留 CPU 参考调用；Viewer 默认 GPU 动态模式，可切回 CPU。第一版只有视锥剔除，没有 HZB、GPU 持久工作队列、Software Rasterization 或 Streaming；CPU 仍整理静态 Group 深度并为全部候选录制单条索引间接命令，Resolve 也仍按全部候选编排，未声称已消除 CPU 提交或全屏 Resolve 开销。

### 开发中定位的问题及修正

1. **RDG RWStructuredBuffer 元素结构体未输出。** GlobalShader 初始化报告 `Failed to compile VirtualGeometrySelectGroupsCS` / `VirtualGeometrySelectClustersCS`。预处理文本存在 `RWStructuredBuffer<VirtualGeometryGPUWord>`，却没有对应元素结构体定义。上层已按约定使用 SHADER_PARAMETER_RDG_RWSTRUCTURED_BUFFER，并携带 StructMetadata；[ShaderCompiler.cpp](../../../src/Framework/RenderCore/Private/ShaderCompiler.cpp) 的 EmitNestedRecursive 只接受 RDGBuffer_SRV、RHI_SRV/RHI_UAV 等，漏了 RDGBuffer_UAV。修正只在原判断中加入该枚举，不手写另一套参数系统。

2. **Buffer UAV 判空前读取触发访问异常。** Windows 调试器捕获访问地址 104，栈顶为 RenderGraphBuilder::SetupPassInternal，由 GPU 选择 Pass 的 AddPass 调用。Group 阶段没有使用 Finalize 的输出 UAV，参数中的这些引用合法为空；但 [RenderGraphBuilder.cpp](../../../src/Framework/RenderCore/Private/RenderGraphBuilder.cpp) 在 `if (uav)` 前执行了未使用的 `auto uavDesc = uav->m_Desc`。仅删除这行，实际访问意图仍在判空后按原逻辑登记。没有新增 Pass 接口、访问容器或保活机制。

3. **OpenGL Buffer UAV 未绑定。** 首个正交、零预算、关闭剔除的用例读到 Cluster 0 flags=0，而 CPU 预期为 3，即完整叶 Cut 且可见；真实 GBuffer 渲染也得到 0 个模型像素。上层已传入有效 Buffer UAV，SPIR-V/GLSL 已编译，Vulkan/D3D12 对照通过。[OpenGLContext.cpp](../../../src/Framework/RHIOpenGL/Private/OpenGLContext.cpp) 的 UAV 分支只绑定 Texture UAV，Buffer 分支原注释声称“无需显式绑定”。实际 Compute 的 SSBO 因而没有目标绑定。修复按视图 Offset/Size 调用 glBindBufferRange(GL_SHADER_STORAGE_BUFFER)。复测首用例和全部阈值通过，模型像素恢复为 1926。

4. **OpenGL Transition 原为空实现。** 多批 Group Dispatch 必须看到前置 Group 写入，Compute 写入的参数也必须对间接绘制可见。OpenGLRHIApi 先前仅预留了占位转换大小，Begin/EndTransitions 未发屏障。现沿既有 RHITransition 私有数据保存 GLbitfield，EndTransitions 记录 worker 上的 glMemoryBarrier；转换在 OpenGLUtils，覆盖 UAV→UAV、UAV→IndirectArgs 及其他实际消费状态。没有用 glFinish、WaitIdle 或 CPU 逐 Dispatch 等待代替屏障。

5. **新图测试夹具缺少属性。** 最早的人工 DAG 只填写 Position/Index，InitializeResources 按现有不变量拒绝上传并报告 `cannot upload mismatched vertex attributes`。补齐夹具的 Normal/Tangent/UV/Color，未放宽资源校验。夹具只验证图逻辑，不被当作实际 Build 几何的边界证明。

失败的 OpenGL 诊断进程在异常后未自行结束，测试驱动超时终止。进程已退出后，旧运行目录映像仍被映射，完整链接出现 LNK1168/LNK1104。先在忽略目录输出完整运行环境完成检查，再将旧构建产物移入已核对路径的忽略诊断目录并重新完整链接，主运行目录最终构建成功；没有删除源码、改构建配置或降低测试断言。

### 实际球体预览与 GPU 调试

独立诊断直接编译本模块 VirtualGeometryPreview.cpp，并从已有工程快照恢复 559 顶点、960 面球体及材质；Viewer 为其构建自己的 23 Cluster、9 Group、1 Root、6 生成层资源，不修改原网格。相同相机、320×240 视口，逐一检查 0/0.5/1/4 像素预算。

- Vulkan 和 DirectX12：CPU/GPU 各检查 Cluster/材质光照两模式及线框开关，每后端 16 对图像。
- OpenGL：CPU/GPU 检查 Cluster 模式及线框开关，8 对图像；独立材质光照预览仍未纳入此次检查。
- 合计 40 对、80 帧 CPU/GPU 离屏图像逐像素一致。GPU Capture 的完整 Cut 差异全部为 0。4 像素预算选择 8 Cluster、556 面，含 0/1 混合层。源工程全部文件哈希一致。
- GPU 线框没有改用 CPU Cut：Viewer Compute 从同一三角形参数生成线段参数，再执行 LineList 索引间接绘制。共享边可能重复、全部候选线索引每帧上传的成本如实保留。

可见结果保存在忽略目录 sphere-gpu-viewer-*.png / .ppm，诊断入口 run_gpu_viewer.py；它不是仓库依赖。功能配置和快照语义见 [Viewer 使用约定](../../specification/virtualgeometryviewer_spec.md)。这组验证是实际 GPU 像素读回，不等同于鼠标操作界面验证。
