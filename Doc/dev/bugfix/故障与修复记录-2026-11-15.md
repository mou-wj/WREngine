# 故障与修复记录 - 2026-11-15

## Virtual Geometry GPU Cluster Culling / LOD Selection

### 目标与实际范围

将已完成的 CPU Group DAG 选择迁移到 Compute，并复用原 Visibility Raster、属性恢复和 GBuffer 链路。用户随后允许补充 RHI 间接绘制，因此正常渲染直接消费 GPU 参数，不依赖每帧读回后再由 CPU 决定 Draw 列表。

独立入口为 [VirtualGeometryGPUSelection](../../../src/Framework/Renderer/Private/VirtualGeometry/VirtualGeometryGPUSelection.cpp)，公式、合法 Cut 证明、布局、剔除及复杂度见 [LOD 专题](../../key_implemetion/algorithm/13-virtual-geometry-lod-selection.md)。RHI 命令沿现有 CommandList/Context 分派到三个后端，所有权、工作线程和屏障见 [RHI 完成点专题](../../key_implemetion/performance/02-rhi-queues-and-sync.md#索引间接绘制与-gpu-生成参数)。Engine Build 结构、VertexFactory、传统主场景延迟流程和材质求值逻辑没有重做。

GPU 场景构图入口与 Viewer 已开启此流程。低层 VirtualGeometryInstance::bGPUSelection 默认 false，保留 CPU 参考调用；Viewer 默认 GPU 动态模式，可切回 CPU。第一版只有视锥剔除，没有 HZB、GPU 持久工作队列、Software Rasterization 或 Streaming；CPU 仍整理静态 Group 深度并为全部候选录制单条索引间接命令，Resolve 也仍按全部候选编排，未声称已消除 CPU 提交或全屏 Resolve 开销。

### 开发中定位的问题及修正

1. **RDG RWStructuredBuffer 元素结构体未输出。** GlobalShader 初始化报告 `Failed to compile VirtualGeometrySelectGroupsCS` / `VirtualGeometrySelectClustersCS`。预处理文本存在 `RWStructuredBuffer<VirtualGeometryGPUWord>`，却没有对应元素结构体定义。上层已按约定使用 SHADER_PARAMETER_RDG_RWSTRUCTURED_BUFFER，并携带 StructMetadata；[ShaderCompiler.cpp](../../../src/Framework/RenderCore/Private/ShaderCompiler.cpp) 的 EmitNestedRecursive 只接受 RDGBuffer_SRV、RHI_SRV/RHI_UAV 等，漏了 RDGBuffer_UAV。修正只在原判断中加入该枚举，不手写另一套参数系统。

2. **Buffer UAV 判空前读取触发访问异常。** Windows 调试器捕获访问地址 104，栈顶为 RenderGraphBuilder::SetupPassInternal，由 GPU 选择 Pass 的 AddPass 调用。Group 阶段没有使用 Finalize 的输出 UAV，参数中的这些引用合法为空；但 [RenderGraphBuilder.cpp](../../../src/Framework/RenderCore/Private/RenderGraphBuilder.cpp) 在 `if (uav)` 前执行了未使用的 `auto uavDesc = uav->m_Desc`。仅删除这行，实际访问意图仍在判空后按原逻辑登记。没有新增 Pass 接口、访问容器或保活机制。

3. **OpenGL Buffer UAV 未绑定。** 首个正交、零预算、关闭剔除的用例读到 Cluster 0 flags=0，而 CPU 预期为 3，即完整叶 Cut 且可见；真实 GBuffer 渲染也得到 0 个模型像素。上层已传入有效 Buffer UAV，SPIR-V/GLSL 已编译，Vulkan/D3D12 对照通过。[OpenGLContext.cpp](../../../src/Framework/RHIOpenGL/Private/OpenGLContext.cpp) 的 UAV 分支只绑定 Texture UAV，Buffer 分支原注释声称“无需显式绑定”。实际 Compute 的 SSBO 因而没有目标绑定。修复按视图 Offset/Size 调用 glBindBufferRange(GL_SHADER_STORAGE_BUFFER)。复测首用例和全部阈值通过，模型像素恢复为 1926。

4. **OpenGL Transition 原为空实现。** 多批 Group Dispatch 必须看到前置 Group 写入，Compute 写入的参数也必须对间接绘制可见。OpenGLRHIApi 先前仅预留了占位转换大小，Begin/EndTransitions 未发屏障。现沿既有 RHITransition 私有数据保存 GLbitfield，EndTransitions 记录 worker 上的 glMemoryBarrier；转换在 OpenGLUtils，覆盖 UAV→UAV、UAV→IndirectArgs 及其他实际消费状态。没有用 glFinish、WaitIdle 或 CPU 逐 Dispatch 等待代替屏障。

5. **新图测试夹具缺少属性。** 最早的人工 DAG 只填写 Position/Index，InitializeResources 按现有不变量拒绝上传并报告 `cannot upload mismatched vertex attributes`。补齐夹具的 Normal/Tangent/UV/Color，未放宽资源校验。夹具只验证图逻辑，不被当作实际 Build 几何的边界证明。

失败的 OpenGL 诊断进程在异常后未自行结束，测试驱动超时终止。进程已退出后，旧运行目录映像仍被映射，完整链接出现 LNK1168/LNK1104。先在忽略目录输出完整运行环境完成检查，再将旧构建产物移入已核对路径的忽略诊断目录并重新完整链接，主运行目录最终构建成功；没有删除源码、改构建配置或降低测试断言。

## Virtual Geometry GPU Software Rasterization

### 范围与设计取舍

沿用既有 GPU Cut、Cluster 剔除和稳定间接参数，新增 [VirtualGeometrySoftwareRaster](../../../src/Framework/Renderer/Private/VirtualGeometry/VirtualGeometrySoftwareRaster.cpp) 及四个 Shader 文件，由原 Raster 入口按可选设置编排。Hardware 默认行为不变，Viewer 默认 Hybrid，SoftwarePreferred 仍保留裁剪/尺寸安全回退。主场景 RenderModule、DefferedSceneRenderer、Engine Build/DAG、VertexFactory、Material Resolve 和 GBuffer 布局未改。

软件路径用两遍 Compute 完成深度与 ID 归约，最终全屏合并硬件结果并输出真正的 D32。未扩展 64 位原子、深度 UAV、RenderGraphPass/Builder、生命周期或队列体系。RHI 仅补充原生子像素位数能力；OpenGLUtils 修复测试必需的 D32 读取格式。公式、32 位原子一致性、内存和性能代价见 [算法专题](../../key_implemetion/algorithm/14-virtual-geometry-software-rasterization.md)，用户操作见 [Viewer 约定](../../specification/virtualgeometryviewer_spec.md)。

### 开发中遇到的问题

1. **未使用的另一阶段资源仍被反射。** 早期 DepthCS 用运行时 bool 选择深度/ID 写入，Vulkan 报描述符校验 08114；上层只绑定本阶段需要的资源，而 Shader 反射仍保留 WinnerDepth/SoftwareVisibility 等另一阶段绑定。改用 SOFTWARE_WRITE_VISIBILITY 编译变体，阶段代码和绑定一致，不用无意义占位资源或改参数架构掩盖问题。

2. **Vulkan 软件覆盖上下颠倒。** 原 Resolve 的 ScreenYSign 判断被直接套用到软件屏幕变换，初次 HW/SW 对比出现 14 个 ID 缺失；读回同一片元软件位置 y=45、硬件 y=79。实际 VulkanPendingGfxState::SetViewport 在内部将高度取负，软件必须和 D3D12 一样使用 -1，OpenGL 使用 +1。只修正新软件路径，没有借此全局改动既有投影/材质流程。

3. **子视口被 BeginRenderPass 覆盖。** 新边界测试用原点 (7,5)、尺寸 93×79、附件 111×97。DirectX12/OpenGL 在纯 Hardware 基线就写出视口外像素。上层先 SetViewport/Scissor，再 BeginRenderPass；两个后端在 BeginRenderPass 内按完整 RenderArea 重设状态，和之后软件按子视口覆盖的结果不匹配。最小修复是在 VG Raster 的 BeginRenderPass 后设置请求的 Viewport/Scissor，不修改后端或其他渲染器。

4. **覆盖量化和深度平面不一致。** 覆盖已用原生 8 位子像素坐标，深度仍按未量化 XY 建平面。窄斜三角形测试的 ID 一致，但 D32 最大差异约 Vulkan/D3D12 6.31809×10⁻⁶、OpenGL 3.09944×10⁻⁶，超过原断言。修正深度重心计算使用同一量化后顶点，复测三后端最大差异 5.96046×10⁻⁸，没有放宽深度阈值或对遮挡加容差。

5. **OpenGL D32 读回格式错误。** 原 GetOpenGLTextureFormat 无 D32_Float 分支，MapReadTexture 用 GL_RGBA 读取深度纹理导致 GL_INVALID_OPERATION；历史空场景集成测试因此失败。此次为真实深度对比，在 Utils 增加 GL_DEPTH_COMPONENT，原流程与断言保持不变，空场景测试最终三后端均通过。

新边界夹具最初漏建材质槽，随后又放入重复反向几何面，分别被 Build 以 `invalid section material slot` 和 `duplicate geometric face (including opposite winding)` 拒绝。修正新测试数据为真实槽位、不同几何面的等深重叠，未放宽生产构建校验。早期失败进程部分未正常退出并由驱动超时终止，不记为测试通过。

## Virtual Geometry Geometry Streaming / Compression

### 范围与实现

新增 Engine 的 [VirtualGeometryPages](../../../src/Framework/Engine/PublicHeader/VirtualGeometryPages.h)，将现有 Build 输出无损打包到可独立读取的 `.vgpages`；Renderer 的 [VirtualGeometryStreaming](../../../src/Framework/Renderer/Private/VirtualGeometry/VirtualGeometryStreaming.h) 管理每资源的物理 Page Cache、GPU 驻留、请求、任务与预算。实例显式附带同一个 Cache，多个实例合并 GPU 请求；Viewer 默认启用，CPU/生成层检查恢复原全量模式。主场景 RenderModule/DefferedSceneRenderer、材质 Helper、Material Resolve、GBuffer 和 VertexFactory 未改实现。

页内 XOR/Varint、格式/目录校验和位级往返见 [压缩专题](../../key_implemetion/algorithm/15-virtual-geometry-page-compression.md)。GPU 驻留闭包、物理重定位、预算范围、后台 TaskPool、上传与读回完成点见 [工程专题](../../key_implemetion/performance/11-virtual-geometry-streaming.md)。根 Cut 固定常驻，预算不足拒绝初始化或阻止细化，不以丢面满足预算。没有 GPU 压缩解码、CPU 源几何淘汰、AssetManager 新体系或新的 RHI/RenderGraph 架构。

### 关键问题、证据和修正

1. **缺页不能按 Cluster 独立跳过。** 原选择从最细叶集合粗化，若直接过滤缺页叶，会丢失 Group 的局部覆盖；若按树找单个 Parent，又不符合现有多对多替换。最终保留 DesiredGroups，GPU 队列对“应用 Group 必须应用全部 Child 的生成 Group”和“生成的非驻留 Parent 必须被其消费 Group 替换”求闭包。缺失叶同样强制其消费 Group；每个 Group 入队最多一次。最终 Cut 仍是完整可达替换序列，且所有终点驻留。

2. **初版逆向细化要求中间页常驻，造成无效往返。** 球体 5 页、3 槽预算时，根向下的初版选择会在较细页已加载后，因为中间页被淘汰而又回到根，12 帧诊断后依次出现 cut=1/5/1/3，加载/淘汰累计 28/26。改为上述缺页闭包后，只要最终细层已驻留就无需中间层链：相同输入稳定 cut=10、960 面，加载/淘汰停在 4/2。仍允许真正装不下目标 Cut 的预算产生反复加载，未宣称解决全部调度抖动。

3. **只统计属性池会漏算预算。** 预算计算现在先扣除持久 DAG 元数据和 Residency/ClusterPages/Feedback，再决定槽数。CacheBytes 是申请字节，另外明确排除驱动对齐、staging、临时 selection 和渲染附件。固定槽有内碎片：平面样例有效几何载荷 137,992 字节，但 6 个完整槽和元数据占 335,664 字节，不能拿磁盘压缩率冒充显存压缩率。

4. **既有 QueueType/Value 等待未执行。** RDG 按这两个字段传依赖。VulkanQueue 虽计算 rhivkSyncPoint，随后仍转换 waitInfo.SyncPoint，空指针分支被跳过；DirectX12Queue 则直接忽略无 SyncPoint 的项。两处均改为解析实际队列同步点并执行原生 GPU 等待，保留显式同步对象及原资源依赖，不加入 CPU WaitIdle。

5. **并行录制的读回所有权表缺锁。** 流送反馈和其他 Pass 的 MapReadBuffer/MapReadTexture 可以在录制线程并发插入原 RHIApi map，Unmap 还会移除。Vulkan/D3D12 给这些既有容器加局部 mutex，D3D12 packed-readback 表也在同一锁内维护。没有添加 staging 管理器、跨帧全局保活或把 GPU 等待放进锁内。

6. **此前 Vulkan“超时”实际弹出了 CRT 断言框。** 两轮流送测试分别停在首帧或次帧，旧 SoftwareRasterTest 也在纯 HW 首帧通过后停住。最初没有校验错误，不能仅凭重跑成功称已修复。后续通过暂停诊断子进程、读取线程栈及断言文本取得：`RHIVulkan.dll`，MSVC `include/vector:269`，`can't dereference out of range vector iterator`；栈包含 `std::_Vector_iterator<VulkanMemoryBlock::FreeRegion>::operator-> → VulkanMemoryBlock::Allocate → VulkanMemoryManager::Allocate → VulkanStagingBuffer`。RDG 在 TaskPool 上并行创建 staging/参数缓冲，原 VulkanMemoryManager 对 m_Blocks 和 free list 的 Allocate/Free/Reset 无锁，另一个线程的切分、追加或合并使迭代器失效。只在原管理器对象内给三处入口加同一 mutex，未改分配算法。修复后原软光栅和新流送均通过；断言进程先前被诊断驱动终止，未记为正常退出。原软件光栅章节中的“尚未定位”是取得这次证据前的历史状态。

7. **新跨组测试读取了错误的完成点。** OpenGL 首轮图夹具报告 `cut cannot reconstruct all leaves`，Vulkan/D3D12 对照通过。测试从 transient Flags 的图包装 Tracker 取 Fence，其值没有代表真实底层 transient 分配的完成点，随后同步读回可能早于队列执行。修正新测试，等待同一 Finalize 写入、随后读回的 Cache 外部 Feedback Buffer 的提交 Fence，并断言值非零；未放宽 Cut 判断或改生产选择算法。

8. **大元数据不能放入 64 KiB raw arena。** Page 几何虽小，全量 Cluster、Draw Metadata、选择调度和清零数组仍可能超过当前 RenderGraphAllocator 单页。相关 VG 上传改为 vector 对象归原图、载荷留在 vector 堆存储，通过 RDG_BUFFER_ACCESS(TransferDest) Pass 调既有 UpdateBuffer，保持依赖和 Fence；没有改 RenderGraphBuilder、扩大分配器或引入保活概念。这是基于现有分配器边界的预防性修正，未宣称已做超大模型压力基准。

目录校验覆盖 Page/Cluster 位置表与 Pinned 值，来源摘要拒绝“Cluster 数相同但几何已改变”的归档；损坏数据页保留失败状态和完整粗 Cut。资源已有活动 Cache 时拒绝第二个，销毁时在本对象任务与 GPU Fence 退役后释放物理池，保留 CPU Build 数据。

### 验证入口与实际范围

`Tests.exe -test=VirtualGeometryStreamingTest -rhi=Vulkan`，另选 DirectX12/OpenGL。该真实 Build 输入为 24×24 单元、1152 面平面，30 Cluster、11 Group、6 Page：

- 全属性/索引逐位压缩往返、重新打开归档、损坏目录拒绝、不同来源拒绝。
- 3 槽低预算、6 槽足预算、损坏非根 Page、1 槽仅根预算，共 108 帧；每帧读取 Cut、间接物理地址、Visibility/D32 和 GBuffer BaseColor，逆替换实际 Cut 检查能恢复全部叶。
- 每阶段另外连续提交 6 个图，不逐帧等待，使用共享同一 Cache 的双实例，最后等待实际附件完成点，共 24 个在途验证图。
- 固定平面轮廓始终 7396 个像素；低预算确实加载/淘汰，足预算收敛到 14 个原始叶，坏页只增加失败计数并保留粗层，仅根预算记录 BudgetBlocked 且不加载无容量的细页。
- 载荷从 137,992 压到 48,845 字节；总文件还有头和目录。3 槽申请 169,776 字节，6 槽 335,664 字节，仅根 59,184 字节，均不超各自预算。这组小输入的槽碎片如实保留，不宣称任意 Cache 都比全量紧凑 Buffer 更小。

`VirtualGeometryStreamingDAGTest` 是单独的图逻辑夹具：12 Cluster、7 Group、3 Root，两个原 Group 的 Parent 被不同上层消费，并含两个停滞叶岛。32 帧预算变化和渐进驻留，对比 CPU 闭包、逆替换证明、停滞根保留与最终叶 Cut。它不被当作真实 Build 的几何边界验证。

Debug 的 Tests/Langcher 最终构建成功，仍有既有编译警告。上述 StreamingTest、StreamingDAGTest 在 Vulkan、DirectX12、OpenGL 的最终六项全部退出 0，无测试或校验错误；包括最后增加的目录校验和与来源识别检查。原 SoftwareRasterTest、GPUSelectionTest、ResourceRHITest、GPULODRenderTest、MaterialResolveTest 也在三后端回归通过，保留原断言和流程。最终日志为忽略目录 streaming-final-build.log、streaming-final-validation.log、streaming-regression-summary.log 和 streaming-delivery-tests.log；前面的 CRT 断言及测试完成点修复仍按上述证据单独记录，没有用通过结果抹去历史失败。

### 球体 Viewer 与 Launcher

离屏诊断直接编译实际 VirtualGeometryPreview.cpp，读取现有工程快照中 559 顶点、960 面球体，生成 23 Cluster、9 Group、5 Page。使用 180,000 字节预算、实际 3 槽，检查两个误差预算、Cluster 实心/线框和 Hardware/Hybrid。三后端共六个进程全部退出 0，无校验错误，GPU Cut 与 CPU 驻留参考差异 0；最终均为 3/5 页、申请 168,940 字节、加载 4 次/淘汰 2 次，稳定选择 10 Cluster、960 面。源工程所有文件哈希不变。

Hardware 与 Hybrid 的上述图像共 12 对逐像素一致，另实际查看球体实心和线框读回图确认形状完整。这项只覆盖 Cluster 预览，不声称完成 Lit Viewer 或 GUI 手动点选验证；材质恢复依据前述 GBuffer 读回和原 MaterialResolve 回归。日志及图像在忽略目录 streaming-viewer-final-summary.log、sphere-streaming-viewer-*.ppm。

主运行目录启动 `Langcher.exe -app=Editor`，日志确认面板初始化及 `First scene and GUI frame submitted`，进程保持响应并留作手动检查，未验证正常关闭。streaming-launcher.stdout.log / .stderr.log 仍记录四个既有全局 Shader 编译失败（GlobalDiffuseLightMapInitCS、GlobalDiffuseLightMapDiffuseCS、HZBOcclusionTestCS、ScreenSpaceReflectionDepthPyramidCS）及 Vulkan pCode-08737，不记为整套应用无错误通过。流送及选择 Shader 已经三后端专项执行。

### 最终范围复核与边界

RenderCore、RenderGraph、主场景编排、Material Resolve 和材质 Helper 没有改动；后端修改限于原等待解析、既有读回表并发和已捕获的 Vulkan 内存 free-list 竞争。没有新 RHI 接口、WaitIdle、全局流送管理器或测试主流程变更。UTF-8、本地文档链接、504 个源文件的行数/原始摘要及差异空白检查通过。

CPU 全量几何仍保留、单 GPU invocation 的闭包尚未并行优化、Page 内碎片与有限预算下调度往返、OpenGL 同步反馈读回，以及任意复杂模型的全面裂缝/性能压力审计均为当前边界。文件读取与解码总时间已经统计，但没有纯 GPU 上传时间、全局显存预算或大型场景吞吐基准。
