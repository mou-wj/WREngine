### 调试过程中发现的问题

最初独立诊断程序直接分配完全无灯光的 Scene，首次 BeginRender 在进入扩展之前就停滞/异常。该输入与当前编辑器预览场景初始化不同；诊断程序随后改为复用原 EditorScene 初始化及其公开组件 SceneOwner，不修改产品的初始化流程。没有将完全无灯光场景问题宣称为已修复。

只读深度错误的源码依据：RDG 根据 DepthStencil.bWriteDepth=false 声明 DSVRead；[VulkanRenderPass.cpp](../../../src/Framework/RHIVulkan/Private/VulkanRenderPass.cpp) 的深度附件 initialLayout/finalLayout/reference layout 固定为 DEPTH_STENCIL_ATTACHMENT_OPTIMAL，与实际转入的 DEPTH_STENCIL_READ_ONLY_OPTIMAL 不一致。只读变体保留用于暴露此问题；另一个 DSVWrite 访问声明的检查只证明当前附件路径可执行，不替代只读能力验收。本轮未改变 RHI 或后端转换，也未添加 ImageLayoutManager、WaitIdle 或保活列表。

既有 GlobalDiffuseLightMapInitCS、GlobalDiffuseLightMapDiffuseCS、HZBOcclusionTestCS、ScreenSpaceReflectionDepthPyramidCS 编译问题以及 SPIR-V capability/重复 TypeImage 校验错误继续保留。DirectX12/OpenGL 启动问题和 Vulkan 只读深度路径需要单独定位处理，不能因 Vulkan 图像断言成功就宣称跨后端渲染与校验全部通过。

## 编辑器右上角方向轴与球体交互

SceneEditor 在本帧 SceneView 中加入绘制扩展；新增私有 EditorViewAxes.h/.cpp 和 shaders/editor/ViewAxes.sf，修改 EditorScene.h/.cpp 接入及处理输入。线列表绘制半轴，三角形球面绘制端点：+X 红、+Y 蓝、+Z 绿，负端点混入白色。点击切换轴侧视图，拖动围绕按下时的相机上方向叠加偏航。没有新增窗口、管理器、Frame 或 GPU 几何缓冲；实现/所有权见 [Editor 架构](../../architecture/app/editor.md)、[UI 核心实现](../../key_implemetion/performance/08-ui-rendering-and-window-lifetime.md)，数学见 [方向轴算法](../../key_implemetion/algorithm/03-transforms-frustum-and-depth.md)。

开发中修正的问题：

- RHIRect 的宽高为 uint32_t，初次列表初始化使用 int 导致窄化编译失败，改为确认正尺寸后的显式转换；Shader 宏接口没有 uint32_t 重载，细分常量使用其已支持的 int32_t。
- 初版先设 viewport/scissor 再绑定管线，当前 Vulkan context 在未绑定管线时不保存这两个状态，产生 07831/07832。按既有绘制调用约定先绑定管线再设置动态状态，未修改后端。
- 初版用片元 discard 去除球面背半球，编译生成本机 VulkanDevice 未启用的 DemoteToHelperInvocation capability，产生 08740，且画面出现破碎点。改为正常的背面剔除；球面外向三角形使用 CounterClockwise 后显示正面光照，移除 discard。轴线仍不剔除，未新增设备 feature、关闭校验或修改 ShaderCompiler。
- 偏航从实际相机偏移/上方向开始，并保存 m_OrbitUp，解决从 Top/Bottom 开始拖动或随后滚轮缩放时回到旧默认角度的问题。4 像素阈值区分点击和拖动，拖动释放不会再触发轴侧切换，失焦清除状态。

## 空工程视口输入与坐标球竖向拖动

用户反馈空工程无法正常操作鼠标、球体向上拖动无响应。本次沿窗口实际入口排查，未发现 EditorScene/SceneViewport 按工程状态禁用鼠标的条件；工程目录检查仅限制导入/资产等业务操作。两个根因分别为：

- ImMainWindow 将 ImSlateRenderer 返回值作为 GUI 捕获依据；旧实现入队本次事件后直接读取上一帧 io.WantCaptureMouse。从 GUI 移入空场景并立即按下时，旧标记仍为 true，导致事件没有转给场景。真实窗口驱动 before.stdout.log 的 STALE_CAPTURE_REPRODUCED=1、sceneButtons=0 保留了失败证据；新打开 popup 的反向漏发也被复现。
- EditorScene 球体拖动只用 dx 旋转，dy 只参与阈值判断，纯竖直拖动不改变相机。早期只采样预计端点中心的检查不足：小角度位移可能仍位于同一个近 10 像素半径的球内。新增前后帧差异断言后，旧实现报 Vertical drag changes the actual rendered frame，确认画面未变化，失败日志为 axis-interaction-before。

修复限定两个既有源文件：ImSlateRenderer.cpp 采用当前坐标的只读鼠标捕获查询，保留 ImGui 既有按下所有权及弹窗/模态；EditorScene.cpp 先按 dx 做偏航，再绕偏航后右轴按 dy 做俯仰，同时旋转 Up。后者无需增加成员，继续使用按下时的偏移/上方向和原 m_OrbitUp，保留焦点、距离及 Top/Bottom 连续性；点击阈值、松开不误切视图及失焦取消仍沿用原逻辑。公式见 [相机算法](../../key_implemetion/algorithm/03-transforms-frustum-and-depth.md)，分发与所有权见 [UI 实现](../../key_implemetion/performance/08-ui-rendering-and-window-lifetime.md)。

中间方案在每个鼠标事件中重调 UpdateHoveredWindowAndCaptureFlags，虽然放开了 GUI→视口输入，但当本帧 MouseClicked 仍为 true 时，它按新的悬停窗口重写 MouseDownOwned。after-refresh.stdout.log 的 GUI_DRAG_OWNERSHIP_LOST=1 和失败断言保留了证据，最终改为只读查询。最初对 ImWidgetBase 重复投递的怀疑没有在此实际继承分派路径中复现，DUPLICATE_POSITION_REPRODUCED=0；未据此扩大修改 ImWidget.cpp。
