# 故障与修复记录：2026-11-02

## 对象行右键删除

场景树原有空白处创建菜单，但对象行没有删除入口。ImListWidget 增加 SetOnItemActions，在项 ID 范围内提供通用菜单绘制回调；右键先选择对应项。SceneEditor 增加 Delete，并向宿主提交目标行索引；EditorApplication 在下一帧、Draw 之前消费，避免列表遍历和 ImGui 绘制过程中销毁组件。关闭或切换工程清空请求，实际 RemoveSelected 继续清除工具借用、等待原完成值、Remove/Flush 后销毁组件。

验证包含右键原先未选中的 Cube 而保留 Sphere、删除光源、删除启用了位移工具的节点以及删除最后一个对象。菜单触发帧的节点数保持不变，下一帧才减少；最后一项删除后，整个属性栏和右侧分隔条隐藏。

## 属性描述与通用 NodeEditor

旧 EditorNodePanel 同时判断网格及各类光源，并直接编写每类节点的控件。当前新增 Engine 的 [ComponentProperty](../../../src/Framework/Engine/PublicHeader/ComponentProperty.h) 与 SceneComponent::DescribeProperties，描述类型、ID、标签、分组、范围、只读、读写回调及变换语义。基类声明状态和 TRS，网格声明资源信息，光源继承并筛选有意义的属性、追加光源参数。

[EditorNodePanel](../../../src/Editor/NodeEditor/Private/EditorNodePanel.cpp) 统一按描述生成控件，已经移除具体网格/光源类型判断。Direction、Range、锥角、非有限值和最小缩放等约束在属性写入回调中执行；天空光不支持的颜色/强度为只读且没有写回调。新增组件只需追加已支持类型的描述，无须新增面板或修改通用 UI。描述仅借用当前组件，不跨帧缓存或持有资产。

真实界面诊断中额外定义一个未接入生产节点类型的组件，只追加 Custom flag 和 Exposure 描述；既有 NodeEditor 自动显示控件，并能通过鼠标/文本输入把布尔值切换、数值改为 7。示例和执行约定见 [核心实现](../../key_implemetion/performance/08-ui-rendering-and-window-lifetime.md#组件属性参数与通用编辑界面)。

## 首版 Visible / Enabled 状态链路（已被下文修正）

本节及下节数字记录首版实现和当时验证，不作为当前语义的验收结果。将两个状态相与不符合网格与光源各自职责，当前规则见后文。

可见性原来仅有 PrimitiveComponent 的字段和未实现查询，光源没有统一状态；PrimitiveComponent 的 MarkRenderStateDirty 还是不转发的占位实现。现将本地 Visible、Enabled 统一放到 SceneComponent，两者均为真时参与渲染；Primitive 转发实际变更通知，网格代理/SceneInfo、空间树和 GPU 活动列表读取有效状态。光源注册及更新同步活动状态，光源数组和 IBL 构建跳过无效项；禁用天空光清空两项 IBL 引用，启用时复用原资产。图标、范围提示和 CPU 拾取同步过滤失效节点；编辑器清除被隐藏/禁用节点的工具借用。

核查还发现光源扁平索引原来可能在仅更新 Point/Spot 时重新从 0 计数。增删光源及有效状态改变会影响后续类型的阴影索引，因此沿原 dirty flags 重建各类数组；只更新某类参数时累加前序类型已有数量，保持连续基址。没有添加索引管理器、WaitIdle、RHI 状态回退或 RenderGraphBuilder 改动。

状态独立保存，隐藏/禁用不会销毁节点、注销资产或改动原可见性。状态当前作用于本组件，不自动继承父状态；框架没有组件 Tick/脚本生命周期，因此不宣称已实现脚本启停。静态全局距离场的既有块缓存动态失效仍不完整，本次只在重建源集合中过滤无效组件，不能保证旧 GDF 贡献立即消失。

## 修正：网格可见性与光源照明、范围分离

首版把 Enabled 放在 SceneComponent，又用 Visible && Enabled 同时筛掉实体、光源贡献、范围和拾取。这使网格出现两个重复开关，也使隐藏光源范围错误地关闭照明，禁用照明后无法继续观察其范围。

当前从 SceneComponent 删除 Enabled 和 IsRenderEnabled，仅 LightComponent 保存 Enabled。网格只用 Visible；光源 Enabled 控制 GPU 光源数组、阴影遍历和天空 IBL，Visible 独立控制 HintRender 范围/箭头及其几何拾取。LightSceneInfo 字段改为 bEnabled，避免继续误称照明状态为可见性。天空光无范围，属性面板只提供 Enabled。光源图标和变换编辑保留，不因关闭照明或范围而无法选择/调整。状态仍沿原组件通知更新，没有新增管理器、等待或 RDG 改动。

修正后独立目录和主目录 Debug Langcher 均编译成功，未修改 src/Tests 流程。独立运行的属性/场景诊断正常退出（4.42 秒），检查网格没有 Enabled、隐藏模型退出 GPU/射线列表、隐藏光源范围不减少照明数量、关闭照明仍可拾取可见范围，以及阴影遍历仅按 Enabled 筛选、天空 IBL 独立启停。

真实 Loop/ImGui 输入诊断正常退出（26.77 秒），验证两类开关、自定义属性生成、变换工具保留、删除与最后一项布局清理。实际 GPU 读回：隐藏平行光箭头改变 425 个像素；范围隐藏后再关闭照明改变 2727 个像素；照明关闭时重新显示箭头仍改变 425 个像素；恢复两个开关与初始图像的差异为 0。比较标准仍为 RGB 绝对差之和大于 18。最初诊断中原点的大立方体遮挡箭头，缩小模型后又发现默认直接光相对于天空较弱；通过公开界面调整诊断模型大小、光源位置/朝向和强度后完成可区分的图像比较，没有为这些诊断条件修改生产绘制实现。

## 聚光灯启停无画面变化

独立实际 Renderer 诊断确认 Enabled 通知生效：开/关时 SpotLightCount 为 1/0。但原实现有以下问题，令启用时的聚光贡献已经为零，看起来像开关失效：

1. Scene::UpdateGPUResourceIfNeeded 把 GetInnerConeAngle/GetOuterConeAngle 返回的弧度直接填入 InnerConeCos/OuterConeCos。Shader 用单位向量点积与其比较；外角 70° 错填约 1.2217，大于点积上界 1，所有点都在外锥判断中返回 0。默认 20°/45° 也没有正确渐变。
2. SceneRenderer::UploadShadowMapInfo 把 AddUploadBuffer 放在“缓冲不存在或容量不足”的条件里。移动、转向或调整锥角时已更新 CPU VP 和阴影图，GPU 访问表却保持旧 VP，采样错误位置，可能让模型全落入错误阴影。相同大小的缓冲不重分配，不代表里面的数据无须更新。
3. 关闭 Cast shadow 后仍有旧阴影分配，着色直接调用固定类型的 ComputeSpotShadow，未走已有 NONE 可见性分派；另外禁用光源的旧活动索引和 operator[] 默认插入会让缓存继续进入访问表。

修复限定在 Renderer 的 Scene.cpp、SceneRenderer.cpp 及共享 SceneParametersHelper.sf：上传时取 cos，复用容量时上传当前非空阴影表，禁用时移除活动索引、缓存遍历用 find 筛选，并复用既有 ComputeShadowVisibility 处理不投影的可见性 1。没有修改 RHI 后端、RenderGraphBuilder、资源等待和 src/Tests 流程。初步还怀疑默认向下方向导致 LookAt 退化；本次实测其基向量长度为 1，没有将这一猜测当根因，也没有修改公共数学接口或阴影 up 逻辑。

同一忽略目录诊断程序在修复前后使用相同光源/模型输入，Visible=false 且关闭地面网格与光源范围叠加，差异来自实际照明。四组开/关像素变化如下（512×512，RGB 任意通道不同计一像素）；每组关闭后与原无光图差异均为 0：

| --- | ---: | ---: |
| 默认 20°/45°、斜向照射 | 7645 | 7645 |

| 移到上方，向下照射 | 0 | 2138 |
