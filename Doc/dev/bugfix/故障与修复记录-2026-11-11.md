# 故障与修复记录 2026-11-11

## VirtualGeometryResource CPU 构建第一版

### 范围与落点

开始时 VirtualGeometryResource.h/.cpp 为已有未跟踪文件，Build 为空，实际签名是 `void VirtualGeometryResource::Build(const StaticMesh* staticMesh)`。继续使用这个入口和成员数组，未创建公开 Builder，也没有改动 StaticMesh、RenderCore、RHI 或 Renderer 的传统行为。头文件仅补上 Build 的 DLL 导出、颜色数组和 Group 的局部几何误差字段；实现仍在同一个 cpp 的 Engine 匿名命名空间中。

实现顺序为输入验证/预处理、初始邻接分簇、前沿邻接分组、Group 整体 QEM、重新分簇、DAG 关系与误差记录、重复分组，最后产生根 Group 并统一验证。算法、属性接缝和异常拓扑策略见 [详细实现](../../key_implemetion/algorithm/10-virtual-geometry-cpu-build.md)，模块范围见 [Engine](../../architecture/engine.md#cpu-虚拟几何构建)。不是完整 Nanite，也没有 GPU 资源构建或性能规模承诺。

### 实施中确认的问题与处理

1. **仅按顶点索引判断邻接会割裂 UV/硬法线接缝。** 将精确位置的几何拓扑与完整属性顶点分开；跨 Cluster 相同属性可重新合并，属性不兼容的几何点锁定。不同材质不进入同一 Cluster，简化也保护材质交界。
2. **固定边界点不保证固定边界边。** 除锁定端点外，试折叠验证 link、重复面、顶点扇、法线/UV 翻转和整个 Group 有向边界多重集合；Recluster 后再次核对边界。四面体的退化终止情况不能只靠公共邻居数量判断。
3. **工作数组中的已移除顶点仍占有旧位置。** 重建折叠代表顶点时只遍历实际引用的三角形角点，避免选到未使用的旧 wedge。不会为了保留候选而增加全局资源容器。
4. **QEM 平面代价并非几何最大偏差。** 使用现有 BVH 和最近距离另做简化前后双向采样，加入归一化查询的数值余量，按孩子累计误差最大值加局部偏差传播。采样及累计值都明确不是严格连续表面误差上界。
5. **粗层优化位置可能伸出原始网格 AABB。** 总 Bounds 随每个追加 Cluster 更新，LOD 球同时合并新几何及历史受影响区域。所有层数据都保留，不能只用叶面包围体概括输出。
6. **VS 通配源码更新与实际执行程序可能不同步。** 首次构建触发 GLOB 更新后，首次运行仍提示 Test not found；核对生成 vcxproj、obj 和注册表，再完成增量构建，新测试已实际执行。没有更改测试 main 或手动绕过注册机制。
7. **编译诊断发现测试中的同一 auto 声明混用 vec3/vec2。** 拆成各自类型推导后重新编译，不改变测试断言。第一版命令过长触发 Windows 命令长度限制，改为按算法段落写入同一个现有实现文件，未引入额外构建模块。

### 验证入口和限制

增加 [VirtualGeometryBuildTest.cpp](../../../src/Tests/VirtualGeometryBuildTest.cpp)，使用既有 Tests 注册表，命令为 `Tests.exe -test=VirtualGeometryBuildTest`。测试不创建窗口、RHI API 或资源，入口及结束都检查 GRHIApi 为空；读取几何只使用 CPU 数据。不修改其他已有测试或参数解析流程。

独立目录初轮用例正常退出 0，5.52 秒；在补充跨旧 Group 重分组、多对多关系、精确 UV 接缝、1e-8/1e8 尺度、正负 BaseVertexIndex 与更多失败输入后，最终独立目录用例 virtual-geometry-cpu-final 正常退出 0，9.91 秒。编译日志 virtual-geometry-build-final-2.log，执行结果和标准输出保存在 out/diagnostics。CPU 用例没有初始化 Shader 编译或图形设备，不将结果推广为 GPU 渲染功能或跨平台性能验证。

主运行目录的 Tests Debug 构建也通过，日志 virtual-geometry-main-build.log、virtual-geometry-main-build-2.log。主目录实际用例 virtual-geometry-main-cpu-final 正常退出 0，10.36 秒，标准错误为空，输出 VIRTUAL_GEOMETRY_CPU_BUILD_TESTS_OK。两目录几何统计相同，汇总见 out/diagnostics/virtual-geometry-verification.json。已有全局 Shader/渲染链未在本 CPU 用例中运行，不声称它们通过；此功能未接入应用启动或绘制，本轮没有启动 Launcher。

最后核查还将位置流索引乘法提升为 size_t，避免极大 CPU 流出现 32 位乘法溢出，并补全标准库头文件。再次在独立目录和主目录构建/运行：virtual-geometry-sky-grid-verify-final 为退出 0、10.44 秒，virtual-geometry-vscode-x64-Debug-final 为退出 0、10.42 秒，两者标准错误为空且均输出通过标记；对应构建日志分别为同前缀的 final-build.log。没有因这次修正降低断言或修改输入网格。构建保留项目已有 TEXT 宏重复定义等警告，没有通过关闭警告或校验来获取通过结果。

最终样例统计（Cluster 数为包含所有层的总数，末级面数由最终前沿取得）：

| 样例 | 原始面 | 末级面 | Cluster 总数 | Group 总数（含 Root） | 成功简化/尝试 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 平面 | 288 | 48 | 7 | 4 | 3/4 |
| 硬法线立方体 | 12 | 12 | 1 | 1 | 0/1 |
| 球体 | 528 | 4 | 16 | 9 | 8/9 |
| 带孔曲面和 UV 接缝 | 1054 | 162 | 25 | 9 | 8/10 |
| 交错材质边界 | 128 | 128 | 128 | 32 | 0/32 |

交错材质样例刻意将相邻面分到不兼容槽，因此产生大量单面 Cluster 并停止简化；这是保护材质边界的保守结果，不冒充满足 50% 的成功。球体最终成为四面体，几何误差相应增大，仍保留全部细层以供后续 LOD 选择。

验证逐 Group 独立重建外边界/材质边界，DFS 检查环，校验各 Cluster 顶点与索引范围、128 面上限、几何/属性有限值、单调误差、球/AABB 和源数据不变。场景包括平面、硬法线立方体、球体、带孔的曲面 UV 接缝、多材质、断开岛、非流形边、退化面过滤和失败后的资源清空。构建器另有始终启用的 ValidateResource，失败不会发布部分数据。

当前明确限制：单套 UV、完全相同位置才识别几何邻接；接缝/非流形区域采用保守锁定而非高级修复；没有高维属性 QEM 或全局自相交认证；每次接受折叠重建组内队列，未优化百万面规模；三角形减半是目标而非保证。没有屏幕 LOD 选择、GPU Hierarchy、Streaming、Visibility Buffer 或 Software Rasterization，也不自动接入传统网格资源初始化。

## 移除异常捕获并整理虚拟几何代码排版

原实现及测试中有多层循环、条件和多条语句挤在一行，影响边界合法性和构建顺序的阅读；Build 也通过 try/catch 在失败时清空资源。现在入口先 Clear，后续在局部 result 中构建，全部验证及统计输出完成后才移动到当前资源。失败自然销毁局部容器并传播异常，当前资源一直为空，不新增清理守卫或管理对象。Build 签名和几何算法保持不变。

VirtualGeometryResource.cpp 和本次新增的测试文件统一整理为四空格、明确的条件/循环代码块及合理断行，简单表达式保留紧凑写法。仅格式化这两个文件，没有给整个仓库增加格式配置。分簇、QEM、边界校验和误差辅助算法经忽略空白、注释和新增控制块括号后的 token 对照保持一致；入口只调整清空和最终发布时机。

测试文件也不再添加异常捕获。正常用例继续使用 VirtualGeometryBuildTest；原 8 个无效输入分别注册为 VirtualGeometryInvalidInput0 至 7，由既有 main 报告校验错误并返回 1，测试对象析构时核对失败结果的全部数组为空且没有初始化 RHI。诊断同时核对具体错误文本、预期退出码和 VIRTUAL_GEOMETRY_FAILED_BUILD_STATE_EMPTY_OK，不把其他崩溃或任意失败当成通过。没有修改 src/Tests/main.cpp 的既有流程。

独立目录和主运行目录 Debug Tests 编译均通过。正常用例分别正常退出 0、9.94 秒和 9.97 秒，13 次成功构建的面数、Cluster/Group、根、简化次数及误差统计逐项与整理前一致。两个目录各自的 8 个无效输入用例均符合预期：退出 1、错误信息匹配且状态清空检查通过。结果为 out/diagnostics/virtual-geometry-style-sky-grid-verify-verification.json 和 virtual-geometry-style-vscode-x64-Debug-verification.json，对应编译日志使用相同前缀的 build.log。没有运行图形设备或 Launcher，也没有将 CPU 检查扩大表述为渲染链通过。

## 虚拟几何统一使用 Core 数学及包围类型

原虚拟几何接口和内部算法直接使用 GLM 向量、矩阵，并将包围球编码为 vec4、AABB 编码为独立的两个 vec3，与 Core 已有类型重复。现在位置、法线、切线、UV 和颜色采用 Core::Float2/Float3/Float4，内部双精度运算采用 Core::Double2/Double3/Double4，Quadric 使用 Core::Mat4d。资源、Cluster 和 LOD Metric 的 Bounds 统一采用 Core::BoxSphereBounds，Box 与 Sphere 分别表达盒及球；移除重复的 BoundsMin/BoundsMax/BoundsSphere 字段，Clear 同时清空包围信息。同步适配全部调用方及新增测试，没有修改 Core、RHI 或传统网格绘制流程。

迁移初轮编译和几何断言通过，但对照旧日志发现球体的采样误差变化。核对发现 QEM 平面归一化的除法与倒数乘法，以及矩阵四项求和的结合顺序会影响舍入，进而改变近似同分候选的先后。恢复原有运算顺序，矩阵按 Core 的行存储访问，仍完全使用 Core 类型。包围球合并保留双精度计算、中心转换误差补偿和半径向上舍入；盒复用 AABB::Merge，避免从盒重建球改变历史 LOD 球的保守包含关系。

独立目录和主运行目录 Debug Tests 均编译通过，正常 CPU 测试分别退出 0、29.89 秒和 30.03 秒，标准错误为空；两套目录各自 13 次构建的日志面数、Cluster/Group、根、简化次数及误差统计与迁移前一致。这是日志输出精度下的对照，不声明所有属性逐字节相同或已完成性能评估。两套目录各自的 8 个无效输入均按预期退出 1，具体错误文本匹配且失败状态清空检查通过。测试额外检查资源/Group 的 AABB 包含、资源球包含顶点，以及同一 Group 的 ChildMetric/ParentMetric 共用相同包围信息。

复查入口保持 Tests.exe -test=VirtualGeometryBuildTest 与 VirtualGeometryInvalidInput0 至 7。结果文件为 out/diagnostics/virtual-geometry-core-sky-grid-verify-verification.json 和 virtual-geometry-core-vscode-x64-Debug-verification.json，构建日志使用同前缀 build.log。代码保留 Core::Float4 的 16 字节对齐导致的 C4324 填充提示，以及项目已有 TEXT 重定义等警告。三个相关源码中不再出现 GLM 引用，未添加 try/catch；本次只验证 CPU 构建，未运行 Launcher 或图形测试。
