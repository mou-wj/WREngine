# 故障与修复记录 2026-11-05

## TextureViewer 来源重复与同名资源区分

本节保留最初去重实现及当时的验证记录。后续明确来源列表只保留资产与生成环境光输出，已移除这里描述的 Runtime 行和三组对象索引；当前行为以下面的“来源列表仅保留资产与环境光输出”一节及现行架构说明为准。

### 现象与已确认原因

Add textures 中同一图片可能重复出现，部分行显示尺寸，另一些行显示 Image file。原 CollectTextureViewerSources 只按 TextureAsset 指针去重；记录了路径却未用路径判重。Content 扫描得到的已加载 Asset 未同步进入对象集合，随后环境光输入又追加同一对象。不同 Asset 包装同一 RenderTexture，以及 Windows 大小写路径别名也可能形成重复候选。

另有一种外观相同的情况：工程加载恢复的无路径 TextureAsset 是独立快照，原来的文件名和尺寸可能相同。原列表仅显示文件名，看起来重复，但不能据此认定其数据相同，更不能直接合并。

实际复现使用真实 Loop/ImGui：工程 Content 放入 A.png，加载后生成环境光，再从 AssetManager 卸下该文件缓存但保留环境输入所有者。修复前 Assets 筛选出现两行 A.png，诊断明确失败，输出 SOURCE_FILE_ENV_INPUT_ROWS 2；修复后同一操作为一行。

### 调整范围与行为

本轮生产实现只调整 [EditorApplication::CollectTextureViewerSources](../../../src/Editor/Editor/Private/EditorApplication.cpp) 及所需 include。候选按 Asset、实际 RenderTexture 和规范路径去重，先登记已有所有者再扫描文件。文件显示 Content 相对路径；独立无路径快照显示 Runtime / 名称，同名加序号，且序号避开原来已含 [1] 等后缀的名称。环境 diffuse/specular 独立结果继续保留。实际数据不同的纹理不按文件名、尺寸或外观合并；同一来源仍允许主动多次加入画布比较子资源。

没有更改 Engine 资产缓存/快照存储，也没有修改 RHI、RenderCore、Renderer、Shader 或 src/Tests。无新增 GPU 等待、像素指纹、全局管理器或保活机制。所有权与索引细节见 [UI 工程实现](../../key_implemetion/performance/08-ui-rendering-and-window-lifetime.md#来源与所有者)，模块边界见 [Editor 架构](../../architecture/app/editor.md#textureviewer-多纹理检查)。此前要求移除的资源文件右键 Open / Add mesh 已从菜单删除，本次主目录完整构建包含该修改；原底部操作按钮仍保留。

## 来源列表仅保留资产与环境光输出

### 原因与修正

上一次仅对已知对象/文件身份去重，仍遍历 CollectProjectAssets、当前纹理选择和环境光输入，导致工程恢复的多个 Runtime 副本继续显示。追加序号虽能区分资源，仍不符合来源页只浏览资产和生成环境光结果的用途。

当前 CollectTextureViewerSources 移除这些额外遍历及 Asset/RenderTexture 指针索引，只保留 Content 图片资产与管理器已生成的 diffuse/specular 输出。文件用规范路径集合去重并显示相对路径，复用已有缓存或延迟加载。环境输出直接用输入资产名标注，不再依赖输入候选行，也没有 Runtime 前缀。材质来源继续保留 TODO。只调整 EditorApplication.cpp 的收集函数；不改工程保存、资产实际所有权、RHI、RenderCore、Shader 或仓库测试流程。

这是收窄浏览来源，不是按名字合并或删除数据：无路径工程纹理和环境输入仍正常存在、使用和保存；若源文件已不在 Content，仅快照本身不会回退为一个候选。不同路径的同名资产仍分别列出；多个真实生成结果也继续保留。同一来源可主动多次加入画布比较 Mip/Face，列表右键 Remove 仍仅移除显示。
