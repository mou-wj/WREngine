# 故障与修复记录 - 2026-11-12

## 虚拟几何接入 RHI 资源

原 VirtualGeometryResource 仅保存 CPU 构建数据，StaticMeshRenderData 未持有它，无法像传统 LOD 一样显式创建 GPU 缓冲。现在 StaticMeshRenderData 新增 VirtualGeometryData，InitializeResources 沿用 RenderCore::RenderBuffer 上传 11 类数组，ReleaseResources 释放全部 GPU 缓冲及视图缓存并保留 CPU 数据；Clear/Build 同时释放旧缓冲。没有新增后端分支、管理器、try/catch 或 WaitIdle，没有自动构建所有导入网格，也没有接入虚拟几何绘制。完整时序及前置条件见 [资源生命周期](../../key_implemetion/performance/05-assets-materials-and-instance-data.md#虚拟几何的-rhi-资源生命周期)。

新增独占缓冲使资源不可复制、可移动。原 CPU 确定性测试为了比较四组数组而复制整个资源，现在仅快照这四组 CPU 数组，保留同样的输入、构建次数及断言，不修改测试 main 或其他测试流程。RHI 初始化先在局部缓冲数组完成创建及同步上传，全部成功才发布；失败自然释放局部对象，旧成员缓冲保留。单缓冲大小受现有 uint32_t 上传接口限制，超限明确失败。

独立目录 Debug Tests 编译通过。VirtualGeometryResourceRHITest 在 Vulkan、DirectX12、OpenGL 分别退出 0，用时 1.66、0.52、1.53 秒，均输出 VIRTUAL_GEOMETRY_RHI_RESOURCE_TEST_OK，标准错误为空，无新增校验错误。用例通过 StaticMeshRenderData 中的真实成员构建 50 面网格，对所有非空缓冲逐字节读回，核对 Size/Stride、上传完成后的 SRV 访问记录，并验证重复初始化、Release 保留 CPU、重复 Release、释放后重新初始化以及 Clear。未以缓冲指针非空替代上传正确性验证。

CPU 构建测试退出 0，用时 7.86 秒，13 次构建日志中的几何与误差统计同原 CPU 实现；8 个无效输入分别按预期退出 1，错误文本及清空标记符合预期。结果在忽略目录 out/diagnostics/virtual-geometry-rhi-verification.json 和 virtual-geometry-core-sky-grid-verify-verification.json；编译日志为 virtual-geometry-rhi-build.log。保留项目已有 TEXT 重定义、DLL 接口及对齐填充警告。

StaticMeshRenderData 布局变更后，主运行目录也重新构建 Langcher、Tests 以及全部编辑器依赖模块，编译退出 0，日志为 out/diagnostics/virtual-geometry-rhi-main-build.log。没有运行 Launcher，本次运行验证由三后端缓冲读回及 CPU 用例承担；不把编译通过表述为界面或传统渲染画面通过。

本阶段没有 Shader 消费、GPU 层级/Culling 或虚拟几何实际绘制验证。Cluster/Group 缓冲为当前 C++ 内存布局，尚不是跨语言 Shader ABI；后续需另行明确布局。释放/重建必须由调用方先完成所有旧 GPU 使用，不能依赖本接口自动等待任意未来提交。

## Virtual Geometry Visibility Raster 与 Cluster Debug

Renderer 的 VirtualGeometry 目录新增继承 VertexFactory 的位置输入工厂，通过 MeshMaterialShaderMap 编译 VS/PS。最细 Cluster 由 CPU 遍历，每个 Cluster 提交一次 DrawIndexed，正确使用 IndexOffset、TriangleCount 和 VertexOffset。Visibility 保存 R32G32_UInt 的 DrawID/PrimitiveID，配套反射 Metadata 保存 InstanceID、ClusterID、ResourceIndex，Debug Pass 据此显示 Cluster 颜色。SceneSetting::bDrawVirtualGeometry 选择该路径，各 SceneView 持有独立 Visibility 和深度。算法和所有权见 [Visibility 实现](../../key_implemetion/algorithm/11-virtual-geometry-visibility.md)。

本次实现遇到并处理了以下实际问题。

- RHI 格式缺少 R32G32_UINT。追加 R32G32_UInt 并补齐 FormatInfo、GetFormatSize 和三个后端 Utils 映射，保留已有枚举编号。
- VertexFactory 编译回调收到的 VFType、ShaderType 字段未赋值。补齐上下文后，工厂能够按 ShaderType 筛选本功能的两个 Raster Shader。
- Vulkan 在片元 Shader 中使用 PrimitiveID 时声明 Geometry capability，逻辑设备没有启用对应 feature。按已查询的支持情况启用 geometryShader，移除该校验错误。
- RDG 的 needBarrier 对两个只读访问直接返回 false，使 SRV 到 TransferSrc 的布局转换缺失，出现 VUID-vkCmdDraw-None-09600。改为比较两个访问状态。Pass 增加 AddBufferAccess/AddTextureAccess，沿用现有访问意向分析及 Fence 更新。位置和索引通过前者声明 VertexOrIndexBuffer，测试读回通过后者声明 TransferSrc。
- DirectX12 Debug Layer 660 报告 TEXCOORD 的 VS/PS 硬件寄存器签名不匹配。PS 原来只声明 DrawID，改为与 VS 共用包含 SV_Position 的 varying 结构。用于定位错误的临时后端诊断顺序调整已恢复。
- OpenGL 索引绘制忽略 vertexOffset，把 instanceCount 乘进 indexCount。改用 glDrawElementsInstancedBaseVertexBaseInstance，传入各自参数。深度比较原先固定 GL_LESS，改为通过 OpenGLUtils 映射真实的 DepthCompareOp，使清屏所需的 Always 生效。
- OpenGL Buffer SRV 分支原先跳过绑定，补充 SSBO 的 glBindBufferRange。ShaderCompiler 的 GLSL 转换为 Texture.Load 生成 dummy sampler 时，缺少对应的纹理 Binding，导致 Debug 取到 DrawID 0。只对 dummy sampler 保留原图像槽位后，Cluster 颜色与 Metadata 相符。
- OpenGL MapReadTexture 是同步读取，放进 RDG 并行录制 lambda 会早于 GPU 绘制。隔离测试对 OpenGL 在已提交工作完成后读取，Vulkan/DirectX12 仍在图内记录读回。三者使用同样的像素断言。测试只初始化本功能消费的三个全局 Shader，避免将无关 Shader 的既有缺失 include 等错误混入该功能验证。

独立目录 Debug Tests 编译通过。VirtualGeometryRasterTest 在 Vulkan、DirectX12、OpenGL 分别正常退出 0，用时 3.55、1.27、1.31 秒，标准错误为空，均输出 VIRTUAL_GEOMETRY_VISIBILITY_TEST_OK。288 面网格生成三个叶 Cluster 与四个粗层 Cluster，两个实例共享资源，总计六条 Draw Metadata。两个相反提交顺序均读回前景 2704 像素、背景 1392 像素，近处实例 676、远处实例 2028，ID 越界、深度顺序及 Debug 颜色错误数均为零。空场景 4096 像素均为双 0xFFFFFFFF。还检查了非零 PrimitiveID、非零 Cluster 顶点/索引偏移、共享 ResourceIndex 和外部位置缓冲的访问 Fence。

复查入口为 Tests.exe -test=VirtualGeometryRasterTest -rhi=Vulkan，也可指定 DirectX12、OpenGL。运行日志及汇总保存在忽略目录 out/diagnostics/virtual-geometry-visibility-*.stdout.log、同名前缀 stderr.log 和 virtual-geometry-visibility-verification.json。此前失败的多轮构建与读回诊断留在同目录，最终结果以通过标记、退出码和空标准错误共同确认。
