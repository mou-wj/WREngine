# 故障与修复记录

## 延迟渲染在 DirectX12 和 OpenGL 的启动及首帧异常

用 `Tests.exe -test=MaterialTransparencyTest -rhi=<后端>` 复现，全局 Shader 加载与首次场景颜色读回是不同阶段。逐步排查得到以下结果。

- **DirectX12 IBL 初始化提交异常。** 转储栈出现 `D3D12SDKLayers.dll` 的访问冲突 `0xC0000005`，调用路径为 `RenderModule::InitIBLLut → DirectX12Queue::ExecuteContext → ExecuteCommandLists`。旧代码取得上下文后直接绑定 PSO、派发和提交。DirectX12 原生命令列表在上下文 Begin 时创建或重新打开，未 Begin 的上下文可能提交空列表指针或已关闭的列表。LUT 初始化现在显式 Begin。后续测试进入了场景实例数据更新，报 `Unsupported DirectX12 RHI resource access bits`。上层把实例变换结构化缓冲声明为 `ShadingRateSource`，而 Shader 通过 SRV 读取。修正实例更新的访问状态为 SRV。环境光生成纹理使用与三后端 UAV 写入相容的 RGBA8 布局。 [初始化](../../../src/Framework/Renderer/Private/RenderModule.cpp) · [实例数据](../../../src/Framework/Engine/PublicHeader/InstanceDataMgr.inl) · [环境光资源](../../../src/Framework/Engine/Private/EnvironmentLightResourceManager.cpp)
- **深度金字塔格式及同步。** 原实现沿用 D32 深度附件描述并同时设置 DepthStencil 与 UAV。DirectX12 禁止这组标志。金字塔独立为 R32F，Mip 0 读原深度，后续 Mip 以相邻单 Mip UAV 读写。生成器改成一个 Mip 一个 RDG Pass，以整链访问意图产生相邻派发的屏障。SPIR-V 编译器以前去掉了所有 Storage Image 格式，OpenGL 因此要求 `GL_EXT_shader_image_load_formatted`；按 Shader 编译环境选择保留 R32f 后，该诊断消失。 [金字塔实现](../../../src/Framework/Renderer/Private/DepthPyramidGenerate.cpp) · [D3D12 资源标志](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/ne-d3d12-d3d12_resource_flags)
- **OpenGL 块布局及图像槽。** SDF 体素化把每 12 字节的顶点位置声明为 GLSL 需要 16 字节对齐的向量结构，使用保持原数据布局的三标量读取。视锥剔除的 AABB 由 CPU 与 Shader 共同使用两个 Float4，明确缓冲步长。主渲染的 ScreenSpaceGICS 之前包含闲置的 `OutputColor` 图像声明，分到绑定 8，超过当前设备 0 至 7 的图像槽。移除闲置 include 后，native GLSL 材质测试到达首帧读回。 [体素化 Shader](../../../shaders/tools/DistanceFieldVoxelizeCS.sf) · [视锥参数](../../../src/Framework/Renderer/Private/FrustumCullPass.h) · [屏幕空间 GI Shader](../../../shaders/tools/ScreenSpaceGICS.sf)

- **网格顶点与像素阶段联接。** DirectX12 进入首帧后报 D3D12 660，顶点输出与像素输入的 TEXCOORD 硬件寄存器不匹配。GBuffer、前向、Mask 深度和透明像素着色器现在共用 VertexFactory 声明的 VSOutput，保留 SV_Position 与插值结构的完整顺序。OpenGL 的受光透明 Pass 还会因不同 include 顺序使 LocalVertexFactoryParameters 在 VS、PS 获得不同的块绑定，先声明共享 VertexFactory 再声明场景资源后，两端一致。 [VertexFactory](../../../shaders/vertexfactory/LocalVertexFactory.sf) · [DXIL 签名规则](https://github.com/microsoft/DirectXShaderCompiler/blob/main/docs/DXIL.rst)
- **OpenGL GPU 读回顺序。** 调试存储图像显示最终 GPU 颜色在目标像素为 (0.4, 0.8, 1.2)，同步 MapReadTexture 则可能收到前一帧或零。旧 MapReadTexture 与 MapReadBuffer 忽略调用方命令列表，由另一个任务列表执行，可先于生产命令或访问转换。两者现在通过命令列表记录，在同一上下文执行，再使用原调用方的 Fence。 [OpenGL readback](../../../src/Framework/RHIOpenGL/Private/OpenGLRHIApi.cpp) · [时序说明](../../key_implemetion/performance/02-rhi-queues-and-sync.md#opengl-的存储写入屏障和读回)
- **OpenGL 跨帧深度清理。** 排序测试显示透明绘制后下一帧变黑。透明 PSO 关闭写深度，清理 Pass 没有 PSO，导致 glClear 继承 GL_DEPTH_WRITEMASK=false 并保留前帧的遮挡深度。清理时临时开启深度写入，清理结束恢复传入值。 [RenderPass 实现](../../../src/Framework/RHIOpenGL/Private/OpenGLContext.cpp)
- **折射偏移的窗口坐标。** 旧 Shader 从折射点的绝对投影坐标减 SV_Position，并固定翻转 Y。OpenGL 下强度为零仍可能获得偏移。现在相减两点的 NDC 后映射到各后端的窗口坐标，以当前片元坐标为采样基准。 [折射 Shader](../../../shaders/material/TransparencyMaterialPS.sf)

- **Vulkan 重复存储图像类型。** Jump Flood 的 Seed 输出是 RGBA32F，距离输出是 R32F。去掉两者的格式会把 SPIR-V 变为两个完全一致的 OpTypeImage，Vulkan 在创建 Shader Module 时拒绝。该 Shader 保留原有类型，距离输出的资源描述采用 R32F UAV。最终 Vulkan 透明场景运行中已没有重复类型或未启用 StorageImageReadWithoutFormat 的诊断。Jump Flood 仍是独立实验路径，默认距离场使用 CPU，未验证实验路径的运行结果。 [生成参数](../../../src/Framework/Engine/Private/DistanceFieldProcess.h) · [距离纹理](../../../src/Framework/Engine/Private/DistanceFieldMgr.cpp)

- **OpenGL 多层附件。** 六材质回归开启级联阴影时有多个 GL_INVALID_OPERATION。旧 BeginRenderPass 把数组阴影纹理和立方体纹理一律作为 GL_TEXTURE_2D 挂接，并丢弃 Slice/Mip。现在按 RHI 视图的层级、立方体面和 Mip 选择对应的 GL 附件调用。修正后六材质和 Volume Pipeline 的 OpenGL 用例正常退出，两个用例未再输出上述 GL 错误。 [帧缓冲附件实现](../../../src/Framework/RHIOpenGL/Private/OpenGLRenderTarget.cpp)

## Alpha Mask、加权混合及分层折射

Masked 的可见路径、预深度实现、主渲染阴影和 Surface Card 捕获复用同一覆盖率判断。DXC 的 Vulkan 1.3 片元目标可把 clip 生成为 `OpDemoteToHelperInvocation`，该操作要求当前 Vulkan 设备未启用的可选特性，也不适合已有 GLSL 翻译路径。片元 SPIR-V 目标采用 1.2，验证使用 `OpKill`。 [Shader 编译入口](../../../src/Framework/RenderCore/Private/ShaderCompiler.cpp) · [覆盖率实现](../../../shaders/core/MaterialParametersHelper.sf) · [DXC SPIR-V 说明](https://github.com/microsoft/DirectXShaderCompiler/blob/main/docs/SPIR-V.rst)

Vulkan、DirectX12 和 OpenGL Debug 的 `MaterialTransparencyTest` 均正常退出。测试用 2×1 灰度 Opacity 纹理验证孔洞透出墙面、实心区域写深度并挡住后方透明面。相同立方体放在聚光路径内时，Masked 覆盖率为 0 的阴影差值为 0，覆盖率为 1 的最大线性 RGB 差值为 0.552446，与不透明遮挡体一致。半透明加权合成读回中心 RGB 约为 (0.475, 0.200, 0.675)，交换相交面顺序后在容差内一致。分层玻璃读到此前透明面，RGB 为 (0.099, 0.400, 1.100)，共享背景时约为 (0.199, 0.800, 1.200)。原混合、折射边界、水面深度和三类光照加 IBL 用例也通过。 [测试入口](../../../src/Tests/MaterialShadingModelTest.cpp) · [算法及限制](../../key_implemetion/algorithm/25-transparency-rendering.md)

## 验证范围及后续

六种材质的 `MaterialShadingModelTest` 在 Vulkan、DirectX12、OpenGL 通过。Vulkan 的 `SurfaceCacheMaterialTest` 和 OpenGL 的 `VolumePipelineTest` 通过，体积测试覆盖遮挡终点、IBL、历史与天空/水面的合成。透明面的独立体积积分、GI 逐区段遮挡、Virtual Geometry Masked 仍待实现。

Vulkan、OpenGL、DirectX12 均通过 `MaterialShaderCompilationTest`，其中包含透明常规与 OIT 变体的 Shader 编译和 RHI Shader 对象创建。隔离目录 Debug 构建目标为 Tests、Editor、Langcher。`Langcher.exe -app=Editor` 使用 Vulkan 启动，窗口提交空工程首帧，正常关闭并返回 0。三后端运行仍有 GlobalDiffuseLightMap、HZB 与独立 SSR 的历史全局 Shader 编译信息。DirectX12 还报告清除值与创建时优化值不一致的性能提示。 [半透明优化记录](../optimize/优化点-2026-11-22.md) · [其他待办](../optimize/优化点-2026-11-23.md)
