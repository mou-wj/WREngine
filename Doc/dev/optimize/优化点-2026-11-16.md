# 优化点 - 2026-11-16

## 范围与状态

本记录整理 Virtual Geometry 当前渲染链路的待完善能力和性能优化方向，依据代码基线 `569f224`。本次仅整理文档，没有实施下列优化或新增运行测试。条目的优先级是建议顺序，不代表已批准的开发计划或已测得的收益。

目前独立链路已经包含 CPU 构建、压缩分页、GPU 驻留与流送、GPU DAG LOD/视锥剔除、间接绘制、软硬件光栅化、Visibility、Material Resolve 和 GBuffer；Viewer 可复用原延迟光照。后续工作应继续复用现有模块职责、参数访问声明和资源 Fence，保持多对多 DAG Cut 合法，不能为优化绕过边界保护或放宽像素正确性要求。

当前接口及接入边界见 [Renderer 使用约定](../../specification/renderer_spec.md)，已执行的验证及其限制见 [2026-11-15 开发记录](../bugfix/故障与修复记录-2026-11-15.md)。优先级 P1 表示建议近期开展，P2 表示在基础成本与正确性明确后推进，P3 表示根据实际需求及测量结果决定。

## 优化清单

### VG-OPT-01：补齐规模基准与 GPU 分阶段测量

- 状态与优先级：待验证、待测量，P1；应先建立基线，再伴随后续各项复测。
- 现状与依据：已有小型网格、跨组 DAG、多实例、软硬件像素对照及流送测试；Viewer 的完成帧计时包含 CPU 构图、录制和等待，不是各 Pass 的纯 GPU 时间。尚无大型复杂模型、多资源紧预算和长期运行的系统压力基准，见 [流送验证边界](../../key_implemetion/performance/11-virtual-geometry-streaming.md)及 [Viewer 使用约定](../../specification/virtualgeometryviewer_spec.md)。
- 影响：不能由功能通过推断吞吐收益，也不能准确确定选择、Resolve、软件光栅或上传各自占比。
- 建议：建立固定模型、相机轨迹、视口和预算组合，分别记录 CPU 构图/提交、GPU 选择/光栅/Resolve/上传耗时、候选与实际可见 Cluster、I/O 延迟、Page 命中和淘汰；区分预热、冷启动及稳态，不在正常帧加入测量等待。
- 验收：三后端保留可复查的配置与基线；覆盖快速移动、近裁剪面、镜像/非均匀实例、混合层边界和长时间淘汰。优化前后同时检查像素、DAG Cut 与预算，不能只比较帧率。

### VG-OPT-02：利用紧凑可见列表减少绘制与软件调度

- 状态与优先级：待实现，P1。
- 现状与依据：[Raster](../../../src/Framework/Renderer/VirtualGeometry/VirtualGeometryRasterPass.cpp) 已使用 DrawIndexedIndirect，但 CPU 仍遍历全部候选，为每个候选录制一个间接命令；未选中项仅将 IndexCount 置零。[GPU Selection](../../../src/Framework/Renderer/VirtualGeometry/VirtualGeometryGPUSelection.cpp) 已输出紧凑可见列表，尚未用于批量提交；软件阶段也仍按全部候选调度，见 [软件光栅成本](../../key_implemetion/algorithm/14-virtual-geometry-software-rasterization.md)。
- 影响：CPU 录制、间接命令和软件工作组数量仍随候选总量增长，剔除并未消除这些成本；实际收益需由 VG-OPT-01 测量。
- 建议：评估按兼容顶点/索引资源和 PSO 分批，消费 GPU 紧凑列表，生成批量间接绘制及紧凑软件 Dispatch。需要 RHI 扩展时先核对三后端能力及回退，保持稳定 DrawID 到 Metadata 的映射，不按紧凑顺序误用原 DrawID。
- 验收：相同可见集合下，候选数量增加时 CPU 命令数及软件工作组不再逐候选线性增加；多资源、多实例、零可见项和跨批次 ID 的 Visibility/Depth/Resolve 结果与原路径一致。

### VG-OPT-03：消除逐候选全屏 Material Resolve

- 状态与优先级：待实现，P1。
- 现状与依据：[VirtualGeometryMaterialResolvePass](../../../src/Framework/Renderer/VirtualGeometry/VirtualGeometryMaterialResolvePass.cpp) 遍历 Draws，每项创建一次覆盖整个视口的 Compute；[Shader](../../../shaders/virtualgeometry/MaterialResolve.sf) 再按 ResolveDrawID 过滤像素。GPU 模式的 Draws 包含全部候选，不仅是可见 Cluster。
- 影响：即使某个候选没有可见像素，仍增加 Pass 和全屏调度；调度规模近似候选数乘视口像素数，是明确存在的重复工作，实际 GPU 占比尚待测量。
- 建议：根据 Visibility 对有效像素或 Tile 分类，按材质/Shader 兼容性组织求值，避免每个 Cluster 扫描整屏。继续复用原材质计算与显式 UV 梯度采样，保留原 GBuffer 编码，不增加独立材质体系或本阶段不需要的 Emissive 通道。
- 验收：空候选和不可见候选不产生逐项全屏扫描；多材质、多实例、Cluster 边界、UV 梯度和法线贴图结果与参考路径一致，记录分类开销和 Resolve 时间。

### VG-OPT-04：增加保守的 HZB 遮挡剔除

- 状态与优先级：待实现，P2；建议在 VG-OPT-01～03 建立基线并减少基础调度成本后推进。
- 现状与依据：[GPUSelection.sf](../../../shaders/virtualgeometry/GPUSelection.sf) 当前按误差、DAG 依赖、驻留及视锥形成 Cut 和可见标志，没有 VG Cluster 的 HZB 遮挡判断。原 Renderer 中存在其他遮挡相关内容，不代表已经接入此链路。
- 影响：被其他物体完全挡住的 Cluster 仍可能执行光栅化，流送请求也可能包含最终不可见区域。
- 建议：利用适用的深度金字塔进行保守包围范围测试；明确使用当前帧还是历史深度，处理近面穿越、相机突变、新出现物体及历史失效。遮挡过滤不能破坏用于驻留回退的完整 DAG Cut，也不能永久阻断缺页恢复。
- 验收：遮挡密集场景中减少实际光栅工作；相机快速移动和遮挡解除时无缺面、长时间消失或错误流送饥饿，与关闭剔除的参考图像对照。

### VG-OPT-05：接入主场景并定义传统路径混合规则

- 状态与优先级：待接入，P2；属于功能完善，不能当作已经完成的场景能力。
- 现状与依据：独立 [AddVirtualGeometryRender](../../../src/Framework/Renderer/VirtualGeometry/VirtualGeomtryRender.cpp) 可以整理场景实例并组合 Raster/Resolve，但主 RenderModule/DefferedSceneRenderer 尚未调用。当前 Raster 和 Resolve 会清空对应附件，不能直接叠加传统 GBuffer，见 [附件契约](../../specification/renderer_spec.md)。
- 影响：Viewer 验证通过尚不能替代真实编辑器场景接入；直接追加调用会覆盖已有深度或 GBuffer，网格也可能被重复绘制或遗漏。
- 建议：明确网格选择 VG 的方式、不支持资源的传统路径规则、实例唯一归属和构建/流送资源所有者；梳理共同清空、传统/VG 深度竞争及 GBuffer 写入顺序。沿用现有场景入口和接口，不因接入另建全局渲染框架。
- 验收：混合场景的双向遮挡正确，网格只参与一条主表面路径，普通网格与 VG 的材质/光照基本一致；覆盖空场景、未构建资源、缺页和动态添加删除，运行 Launcher 验证。

### VG-OPT-06：补齐材质剔除与必要的表面语义

- 状态与优先级：待实现，P2；按实际材质需求逐项推进。
- 现状与依据：[Raster Pipeline](../../../src/Framework/Renderer/VirtualGeometry/VirtualGeometryRasterPass.cpp) 固定 CullMode=None；当前软件路径以双面、不透明、单样本和常规深度为前提，未实现 AlphaTest、顶点位移、软件裁剪、MSAA 或反向 Z，详见 [光栅边界](../../key_implemetion/algorithm/14-virtual-geometry-software-rasterization.md)。
- 影响：不能完整表达材质的前面/背面剔除规则，也不能直接覆盖带孔遮罩等表面；位移会额外影响 Bounds、误差、剔除与驻留选择。
- 建议：优先统一材质 CullMode、双面及实例镜像语义，再按需求支持 Masked/AlphaTest，并定义软硬件一致的覆盖规则。不支持的透明/变形表面可在主场景集成时明确继续走传统路径；不将所有能力视作本阶段必做。
- 验收：前剔除、后剔除、双面和镜像实例行为符合材质；新增遮罩时同时验证 Depth、Visibility、阴影和 Resolve。暂不支持的能力应明确诊断或走约定路径，不能静默按不透明绘制。

### VG-OPT-07：建立 VG 阴影及多视图消费流程

- 状态与优先级：待实现、待集成验证，P2；与 VG-OPT-05 协调。
- 现状与依据：现有 VG 独立链路以调用方的一个 SceneView 为输入，Viewer 可复用延迟光照；尚未打通 VG 自身针对灯光视图的选择、光栅与流送请求流程。主视图 Cut 不能直接代表所有灯光和其他相机视图，见 [Renderer 当前边界](../../specification/renderer_spec.md)。
- 影响：主视图不可见但能投影的几何可能仍需要驻留；不同视图的误差和可见性不能混用。此项不表示传统网格阴影整体不可用。
- 建议：基于原 SceneView、阴影编排和共享几何资源，分别计算各视图的需求，合并 Page 请求并协调预算；明确阴影暂用传统几何时的策略，核对多图间 Fence 和 Cache::EndFrame 的调用契约。
- 验收：主视图外物体仍正确投影，多个灯光/视图共享资源时无错误淘汰、重复请求或生命周期冲突，缺页期间保留完整合法替代层级。

### VG-OPT-08：提高流送调度稳定性并协调多资源预算

- 状态与优先级：待实现，P2。
- 现状与依据：[VirtualGeometryStreaming](../../../src/Framework/Renderer/VirtualGeometry/VirtualGeometryStreaming.cpp) 当前使用每资源预算、一个后台 worker、一次一批 Group 请求；根 Cut 固定常驻，LRU 淘汰非根页，失败页需重建 Cache 后重试。没有跨资源优先级、预取、滞回、限速或系统重试策略，见 [流送工程专题](../../key_implemetion/performance/11-virtual-geometry-streaming.md)。
- 影响：预算不足或相机往返时可能反复加载/淘汰；多个资源各自符合预算，不代表总显存受控；I/O 错误可能长期停在粗层。
- 建议：在现有所有者和 Cache 边界内协调总预算，按屏幕贡献、误差和等待时间排序，增加有界并发、每帧上传限额、驻留保护期及可控失败重试；再评估相机预测预取与 LOD 滞回。不能通过跳过缺页 Cluster 或放松 DAG Cut 合法性减少开销。
- 验收：快速往返和多资源竞争下无几何缺失；统计总申请字节、峰值上传、命中率、请求年龄和反复淘汰次数，验证重试上限及预算不足时的稳定粗层回退。

### VG-OPT-09：改善 OpenGL 反馈读回的阻塞边界

- 状态与优先级：待评估、待实现，P2；不承诺未经测量的帧时收益。
- 现状与依据：流送在反馈完成后调用 OpenGL 现有同步 MapReadBuffer，可能阻塞 worker/调用线程；Vulkan/D3D12 已使用图内 staging 复制与完成值轮询。具体完成点见 [流送读回说明](../../key_implemetion/performance/11-virtual-geometry-streaming.md)。
- 影响：后台文件加载异步，并不等于整条反馈路径完全无阻塞；读回延迟可能影响帧时间或细化响应。
- 建议：先测反馈等待占比，再评估 OpenGL 后端的异步 staging 与延迟消费，或降低反馈频率；尊重现有上下文线程归属及显式完成点，不在上层新增隐式全局等待。
- 验收：正常帧无需等待刚提交的反馈；延迟反馈、跳帧及关闭时映射所有权正确，持续保持合法粗 Cut，记录改造前后的等待时间。

### VG-OPT-10：完善压缩存储与离线派生数据管线

- 状态与优先级：待实现、待测量，P3；按实际内存压力和资产工作流确定顺序。
- 现状与依据：[VirtualGeometryPages](../../../src/Framework/Engine/Private/VirtualGeometryPages.cpp) 已实现磁盘无损 XOR/Varint 与按页读取，但上传后的属性仍完全展开，CPU 原始 Build 数组保留，固定槽有内碎片；`.vgpages` 是派生缓存，尚无完整离线打包和缓存失效流程，见 [分页压缩专题](../../key_implemetion/algorithm/15-virtual-geometry-page-compression.md)。
- 影响：磁盘压缩率不等于显存压缩率，小模型固定槽可能比紧凑全量缓冲更大；运行时构建和 CPU 完整几何也有开销。
- 建议：分别测量磁盘、CPU、GPU 及 staging 峰值；评估更紧凑的页布局、可控量化和 GPU 解码，再考虑 CPU 几何淘汰。量化必须保持共享边界一致，并将新增误差纳入 LOD 约束。离线缓存需明确版本、构建参数、源内容变化、损坏重建和编辑失效规则。
- 验收：记录真实总内存及解码/上传代价；缓存可重建、不可误匹配来源，量化后混合层级无新增边界裂缝，属性误差可解释。不可破坏已约定的工程对象保存与资源所有权设计。

### VG-OPT-11：优化 GPU 驻留闭包及元数据维护

- 状态与优先级：待测量、待实现，P3；若规模基准显示占比高则提前。
- 现状与依据：[ResidentClosureCS](../../../shaders/virtualgeometry/GPUSelection.sf) 当前由一个 GPU invocation 处理有界队列，每个 Group 最多入队一次；[Streaming::Prepare](../../../src/Framework/Renderer/VirtualGeometry/VirtualGeometryStreaming.cpp) 每图上传完整 Residency、ClusterPages、PhysicalClusters 并清空 Feedback，选择调度表也会重新上传。
- 影响：闭包工作仍随元数据规模增长，静态表和未变化状态也消耗 CPU 拷贝、上传带宽及同步；尚未量化这些成本在大模型上的占比。
- 建议：先区分不变表与驻留变化范围，评估持久调度表和按脏区间上传；在保持完整 Group 依赖和缺页传播不变量的前提下评估分层或并行闭包。沿用原 RDG 访问和 Fence，不用 GPU 全局自旋代替正确调度，也不为优化另造全局保活机制。
- 验收：并行/增量结果与现有 CPU 参考及独立逆替换检查一致；覆盖跨组、多根、缺页和在途重定位。静止场景减少无效上传，不能遗漏发生淘汰或槽复用时必须更新的地址与驻留信息。

## 建议实施顺序与维护方式

先完成 VG-OPT-01 的基线，再优先处理 VG-OPT-02 和 VG-OPT-03 的重复工作；随后结合测量推进 HZB，并在进入主场景前明确 VG-OPT-05～07 的深度、材质和阴影契约。流送稳定性及 OpenGL 反馈按压力结果推进；压缩布局、GPU 闭包并行化等进一步优化以成本证据为依据。

后续实施时更新对应条目的状态、实现说明及实际验证记录；新增优化点先检索已有编号与问题范围。以上各项不改变现有已实现能力和测试结果，也不授权本次文档整理顺带修改代码。
