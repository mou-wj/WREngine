# 优化点 - 2026-10-21

## 范围与状态

本记录整理 RHI 光追接口限制和开发中遇到的问题，列出后续工作。各项分别说明现状、改进建议与验收要求；是否已实现或验证以该项记录为准。已修复的具体故障见 [故障与修复记录](../bugfix/故障与修复记录-2026-10-21.md)，OpenGL 后端的当前实现与边界见 [OpenGLRHI 架构说明](../../architecture/rhi/rhiopengl.md)。

OpenGL 软件光追不在本轮范围内。按用户已确认的方案，继续保持能力标记 false 和明确的不支持报错。

## 原有接口限制

- 两个原生后端均使用一个 raygen、递归深度 1；D3D12 为 payload 预留 128 字节、attribute 预留 32 字节。RHI 描述当前没有这些配置项，本次没有扩展 RHI 接口。
- 现有几何描述只提供索引三角形；没有 AABB 几何或独立 any-hit group 描述。本次不声称实现了完整的所有光追功能。
- D3D12 暂不支持无限 descriptor array、TLAS descriptor array 和 shader-record local 参数；遇到不支持的参数布局明确抛错。
- `SetGeometryDesc`/`SetInstancesDesc` 会重建原生存储；Update 用于已构建且保留原生存储的对象，不能把重新分配后的对象直接当作已构建对象 update。

## 优化清单

### OPT-01：光追管线配置与设备限制校验

- 来源：当前只支持单个 raygen、递归深度 1，D3D12 固定预留 payload 128 字节、attribute 32 字节。
- 优化：在 RHI 管线/派发描述中明确 raygen 选择、递归深度、payload/attribute 大小；两个后端按设备支持范围校验，保留兼容默认值。
- 验收：合法配置在 Vulkan/D3D12 中含义一致；超出设备限制时在创建或录制阶段给出明确错误。

### OPT-02：几何与 hit group 描述扩展

- 来源：现有几何描述仅覆盖索引三角形，没有 AABB 几何和独立 any-hit group 描述。
- 优化：明确三角形/AABB 的数据布局及边界检查，使用具名的 closest-hit、any-hit、intersection 描述，避免依赖多个平行数组的位置对应。
- 验收：覆盖三角形、程序化几何和 any-hit 的独立验证，检查两个后端描述转换一致性。

### OPT-03：描述符数组与 shader record 参数

- 来源：D3D12 尚不支持无限 descriptor array、TLAS descriptor array 和 shader-record local 参数。
- 优化：先明确 RHI 数组、计数、索引及记录参数布局，再实现对应描述符与 shader table 数据组织；保持不支持布局的明确报错。
- 验收：覆盖数组边界、多个 shader record 使用不同参数和资源生命周期；不能仅验证管线创建成功。

### OPT-04：区分 AS 描述更新、重建与原位 Update

- 来源：SetGeometryDesc/SetInstancesDesc 会重建原生存储；新存储不能直接作为已构建对象 update。
- 优化：明确创建、首次 Build、Rebuild、Update 状态及兼容条件；容量与结构兼容时评估复用存储，并将实例上传与 GPU 使用的同步纳入检查。
- 验收：验证更新顶点/实例变换、描述数量变化、未声明 AllowUpdate、尚未 Build 就 Update 等正反路径。

### OPT-05：补齐光追验证覆盖

- 来源：现有基础测试不能证明动态更新、多 hit group/callable、非单位实例变换及多队列并发正确。
- 优化：增加独立场景及 GPU 回读断言，覆盖实例 ID/mask、变换、多个 miss/hit record、callable、更新和队列同步，不改现有基础测试主流程来掩盖问题。
- 验收：明确像素/数值预期，记录自然退出与外部停止的区别，并检查 Vulkan Validation 和 D3D12 GPU Validation。

### OPT-06：修复 SPIR-V 存储图像改写

- 来源：Launcher 仍存在 StorageImageReadWithoutFormat 缺失和重复 TypeImage 声明，属于尚未修复的问题。
- 优化：检查图像格式改写产生的类型与使用关系；按实际读写需求维护 capability 和设备 feature，避免重复声明同一非聚合类型。
- 验收：覆盖只读、只写及读写存储图像；修复对应 pCode-08737 错误后重新运行 Launcher。

### OPT-07：完善 GPU 资源退休与退出顺序

- 来源：D3D12 最后一个 UAV 晚于设备析构的问题已用 lifetime token 修复；Launcher 仍有资源在 GPU 使用中销毁的问题。
- 优化：检查视图、图像、framebuffer、descriptor、管线及其设备的生命周期，依据实际队列提交完成值退休资源；避免仅依靠零散的全局 WaitIdle。
- 验收：覆盖正常退出、异常退出、资源重建和设备关闭后的视图析构；对应销毁 VUID 不再出现。

### OPT-08：在保持正确性的基础上细化屏障

- 来源：当前 Vulkan 对交换链 acquire 等待和新增通用内存屏障使用较保守的 ALL_COMMANDS。
- 优化：依据实际首次使用及资源用途推导 stage/access 范围；检查跨队列 buffer/AS 的所有权及 release/acquire 语义，保留可靠的保守回退。
- 验收：先通过同步验证，再比较依赖范围和耗时，不能为了缩小屏障遗漏 AS build/trace、传输或 UAV 访问。

### OPT-09：减少交换链 UAV 中间图像的开销

- 来源：DXGI back buffer 不能直接当 UAV；全局改为 RGBA8 曾导致 BGRA8 图形管线回归。
- 优化：保留对外格式契约，仅在需要时分配内部 UAV 图像；复用视图与转换管线，在原生格式兼容时评估复制路径，减少不必要转换和分配。
- 验收：普通三角形、shaderparameter、光追及不同访问方式切换均正确，交换链实际格式与 PSO/RTV 一致，无黑边或通道交换。

### OPT-10：加强编译元数据、入口与参数绑定的校验

- 来源：DXIL library 需要单独反射，默认 register space 和导出名处理均曾导致故障，现已修复基础路径。
- 优化：检查 shader frequency、register space、入口别名、反射参数与 native binding 的对应关系，明确冲突诊断；为相同入口名、跨阶段同名资源及不同空间增加覆盖。
- 验收：支持的绑定正确映射；冲突和不支持布局给出带资源名、阶段及位置的错误，避免静默绑定到错误槽位。

### OPT-11：保持公开类的跨模块 ABI 一致

- 来源：VulkanRHIApi 的成员曾受后端私有 DEBUG_INFO 宏控制，造成 DLL 与调用方分配大小不同，现已修复。
- 优化：检查其他公开头中控制成员布局的私有宏；为模块与调用方不同编译定义的组合增加构建和运行验证。
- 验收：Debug/Release 和跨 DLL 创建/销毁路径不发生布局不一致；调试开关不改变公开对象的布局契约。

### OPT-12：统一测试入口与验证记录

- 来源：此前不同测试硬编码不同后端，光追测试另用环境变量选择，容易出现启动参数与实际后端不一致。
- 优化：统一 `-test=xxx`、`-rhi=xxx` 的解析、工厂创建与日志；所有测试默认使用 Vulkan，显式 `-rhi` 参数优先于 `RHI_TEST_BACKEND` 环境变量，明确非法参数、未知测试和不支持能力的退出语义。
- 当前进展：本轮已实现统一入口并进行验证；后续可将新增后端/测试选择接入同一入口，持续补充未覆盖的场景。
- 验收：参数顺序不影响结果；显式 -rhi 优先于环境变量；不支持的 OpenGL 光追明确失败，各测试渲染主流程保持原样。

### OPT-13：完善测试异常退出时的资源清理

- 来源：统一入口复验时，OpenGL 光追两次均先正确报不支持，随后以原生异常码 0xC000041D 退出；具体根因尚未定位。
- 优化：排查 Setup/Run 失败后的清理路径，检查资源、窗口回调、后端 worker 和设备的销毁顺序；对部分初始化及异常清理再次失败提供清晰诊断。
- 验收：不支持能力的错误能够稳定返回预期的失败码，不出现原生崩溃或挂起；保持正常测试的 Setup/Run/Teardown 顺序及渲染内容。
- 状态：待排查；本轮仅记录问题，没有改动后端实现或测试渲染流程。
