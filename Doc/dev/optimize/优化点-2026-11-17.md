# 优化点 - 2026-11-17

## 范围与状态

本记录整理 Surface Cache 材质与直接光照缓存开发中确认的能力边界和后续改进方向；两者第一版已实现，各条目分别标明进展，不代表全部优化已完成或已有性能收益。实现与验证依据见 [算法](../../key_implemetion/algorithm/16-surface-cache-material.md)、[生命周期](../../key_implemetion/performance/12-surface-cache-material.md)及 [开发记录](../bugfix/故障与修复记录-2026-11-17.md)。不把明确排除的 Lumen 光照阶段当作本阶段故障。

## SC-OPT-01：提高 Card 覆盖并控制 Atlas 代价

- 状态：待设计、待验证。
- 现状：每实例六张世界轴向 Card，每张只捕获所属实例的最近几何层；固定分辨率与 RGBA32F 调试位置 Atlas，不能保证深凹槽、内壁和薄层覆盖，位置匹配也受像素容差影响。
- 影响：存在明确的无缓存命中；近邻薄层可能在容差内歧义，大量实例会增加 Atlas 内存。
- 建议：先用凹面、薄壳、室内和重复表面建立覆盖率基线，再评估自适应方向/分区、多层捕获及按面积分配分辨率；随后评估压缩格式和位置重建，保留有效位与错层拒绝。
- 验收：按几何命中统计覆盖率和错误材质率，记录内存、捕获耗时及误差；不能用放大容差把错层命中计作覆盖改进。

## SC-OPT-02：场景变更驱动的缓存失效与增量捕获

- 状态：显式全量更新与材质版本核验已实现并验证；Scene 自动驱动和增量调度待接入。
- 现状：SurfaceCacheMaterial 的初始化/释放/捕获推进 Revision；SurfaceCacheDirectLighting 拒绝与当前材质版本不一致的旧 Lighting，支持 Invalidate 和 AddUpdatePasses 全量重算。三后端已验证灯启停/参数、材质重捕获和物体变换，见 [调用与失效](../../key_implemetion/performance/12-surface-cache-material.md#独立直接光照缓存与全量更新)。调用方仍负责在变换、几何、材质、实例 ID 或 SDF 分配变化后退休旧用户、重建并捕获；没有自动绑定 Scene 更新、脏 Card 或每帧捕获预算。尚未加入主场景光照或编辑器面板。
- 影响：上层若遗漏失效会查询旧位置或旧材质，来源资产释放后也不能继续使用旧 SDF Allocation；全量重捕获会增加成本。
- 建议：在真正接入 GI 消费者时复用现有 Scene 变更和材质 Revision，明确失效粒度、资产/实例删除、ID 重用、更新完成前的无效状态及捕获预算；沿用显式 Fence，不另建全局保活体系。
- 验收：动态增删、移动、换材质和 SDF 重建后不读取旧数据；跨帧更新不会提前释放 GPU 仍使用的资源，未更新 Card 明确无效。

## SC-OPT-03：提升局部 SDF 生成与追踪可靠性

- 状态：待修正、待验证；现有生成问题不是本次已修复项。
- 现状：[距离场专题](../../key_implemetion/algorithm/04-distance-fields-and-jump-flood.md) 已说明生成符号、离散采样及旧全局 Helper 的限制；Surface Cache 通过独立局部 SDF 查询保留实例 ID，没有消除这些源数据误差。局部 Atlas 既有默认容量也有限，缺少有效局部 SDF 的实例不参与射线模式。
- 影响：盒网格验证不能推断开放、自交、薄壳、复杂凹面追踪正确；粗容差会提前命中、梯度不稳定或无法匹配有效 Card。
- 建议：先验证并修正生成符号、采样约定、Atlas 生命周期与容量，再对薄层和凹面评估步长、命中精化和梯度策略；明确距离误差和失败状态。若将来复用全局场作粗搜索，仍需对象级精化还原实例，不将最近 AABB 当作真实表面命中。
- 验收：解析盒/球及复杂封闭模型对照三角形参考距离，覆盖正负距离、非均匀变换、近边界、最大步数和多对象最近命中；记录漏检、误检和材质查询失败，不能只看渲染图。

## SC-OPT-04：加速对象级追踪、Card 查找和元数据上传

- 状态：待测量、待实现。
- 现状：[查询 Shader](../../../shaders/GI/SurfaceCacheQuery.sf) 对射线线性遍历所有快照实例，Lookup 线性扫描 Card；Card/Instance 表每图上传，捕获为逐 Card/Section 绘制；直接光照全量遍历 Atlas×Lights，缓存阴影对每个光源投影视图遍历快照 Section，没有灯/遮挡体空间剔除或增量阴影。
- 影响：工作量随实例、Card 和查询数量增加，尚无大型场景吞吐基准，不能由小测试推断性能。
- 建议：先测候选遍历、SDF 采样和捕获占比，再评估复用空间索引、每实例 Card 范围、持久元数据及脏区间上传；不因性能优化改变 ID 语义或覆盖核验。
- 验收：相同输入的最近实例、Card、材质及失败状态与当前参考一致；记录 GPU 阶段时间、Atlas 内存和更新带宽，明确多实例重叠及空场景行为。

## SC-OPT-05：核查 OpenGL 通用跨阶段 UBO 绑定隔离

- 状态：待排查、待修正通用路径；Surface Cache 自身已使用同一 Card 视图常量数据。
- 现状：开发诊断的实际 GLSL 中，VS 独立法线矩阵块和 PS 独立方向块都位于 binding=1，发生覆盖；当前 CompileToOpenGL 计算的阶段偏移没有通过相关 shift 参数应用。Surface Cache 两阶段共享同一视图参数后通过，但不能证明任意不同参数块已隔离，见 [故障证据](../bugfix/故障与修复记录-2026-11-17.md)。
- 影响：其他新图形 Pass 若 VS/PS 恰有不同 UBO 却占相同绑定槽，仍可能出现跨阶段参数污染；这属于后端/编译绑定契约问题。
- 建议：单独审计生成 GLSL、反射打包、program uniform block 绑定与 SetShaderParameters 的槽位映射，统一阶段隔离或真正共享的判定；先检查驱动绑定上限，不能直接把阶段乘 500 当作原生 GL UBO 槽号。
- 验收：建立 VS/PS 同寄存器不同内容、同一共享块、多个材质块和多 Pass 切换的专项断言，确认 UBO 数据互不污染，并回归原 UI、材质和捕获路径。

## SC-OPT-06：缓存阴影的分辨率、偏移与面边界精度

- 状态：基础离屏遮挡已验证；极端尺度、近灯处及 Cube 接缝鲁棒性待改进/验证。
- 现状：[缓存阴影](../../key_implemetion/algorithm/16-surface-cache-material.md#离屏表面的阴影覆盖) 复用 RG16F Shadow Atlas，固定 clip bias=0.001、3×3 PCF，Directional 用整个快照单张正交图；Point 使用六块平面、最大轴选面并块内夹紧。局部灯 near=0.005*Radius，投影不覆盖时保守返回遮挡，容量不足报错。
- 影响：大场景有限纹素覆盖、半浮点深度量化和固定 bias 可能产生 acne/漏光或过度偏移；近面内表面会保守变暗，面边界过滤可能不连续。17 组盒场景通过不能视为这些情况均已验证。
- 建议：用斜面/薄物体、相邻 Cube 面、近灯表面和大范围多物体建立误差对照，再评估高精度深度、世界尺度与斜率偏移、稳定投影和跨面 PCF。保持相机无关覆盖及无覆盖显式状态，不将主视图 CSM 生搬到离屏查询。
- 验收：三后端与几何遮挡参考对照，记录漏光/误遮挡像素、阴影分辨率/内存/耗时；测试 near、far、六面接缝和容量溢出。不能只靠调大 bias 消除自阴影。

## SC-OPT-07：扩展缓存的材质模型语义验证

- 状态：Lambert 漫反射直接 Radiance 已实现；其他模型的逐类型行为待设计/验证。
- 现状：材质 Atlas 只保存 BaseColor、Metallic、世界法线和 Roughness；直接光照统一按 `(1-metallic)*BaseColor/pi` 求值，没有 ShadingModelID 或多瓣信息，未复现原完整 PBR 的视线相关 Fresnel KD。Roughness 在当前 Lambert + GGX 模型中只影响未缓存的镜面项。
- 影响：不能把缓存当成完整材质的最终像素颜色，也不能宣称 Unlit、特殊/自定义 ShadingModel 与传统 PBR 全部逐值一致。未来 GI 消费者需要明确自身适用模型。
- 建议：在增加具体消费者前，明确支持/拒绝的材质模型及所需漫反射系数；若支持 Unlit 或特殊材质，按其真实语义显式携带信息，避免把镜面或 Emissive 混进漫反射缓存。
- 验收：不同材质模型有明确定义和解析参考，保持出射 Radiance/入射 Irradiance 的区别，禁止重复乘源表面反射率；同一模型跨相机视线和 Roughness 变化时符合其定义。

## SC-OPT-08：Screen Probe 缓存生命周期和实际场景验证

- 状态：GIViewer 已默认进入 Scene 预览，提供 Mesh Card 世界空间投影叠加和独立阶段选择；隔离构建及空场景 Launcher 启动通过。`out/pro2` 非空场景中的崩溃原因、各阶段画面、缓存失效和性能预算仍待验证。
- 现状：[LumenViewerRenderer](../../../src/Framework/Renderer/Private/GI/LumenViewerRenderer.cpp) 仅由 GIViewer 调用，在 Viewer 自己的 RenderGraph 中持有当前 Scene 的 Surface Cache Material/Direct Lighting；Scene 模式不会初始化 GI 缓存，选择其他阶段时才按需初始化；Scene 切换会重置，场景内容变化需要用户点击 Build/Rebuild Surface Cache。常规 `RenderModule`/`DefferedSceneRenderer` 不执行 Screen Probe Gather，主渲染与 GI Viewer 隔离。隔离目录构建命令 `cmake --build out/build/screen-probe-vs --target Renderer GIViewer Editor Langcher --config Debug` 成功。Launcher 日志出现 Editor 首帧提交，但同时有 Vulkan `StorageImageReadWithoutFormat`、重复 `OpTypeImage` validation 错误，以及 GlobalDiffuseLightMap、ScreenSpaceReflectionDepthPyramid、HZBOcclusionTest 编译失败。这些错误来自空场景启动观察，尚未确认与 GIViewer 新 Pass 有关。此前默认 Indirect Diffuse 会在 Viewer 每帧构图时加入 Screen Probe 流程；现改为默认 Scene，只在明确选择 Probe 模式时运行，但这只是降低打开时触发的工作量，不能据此确认用户报告的崩溃根因已消除。此次 Launcher 没有加载 `out/pro2`，没有取得其崩溃栈或 GI 图像读回。
- 影响：同一 Scene 发生编辑后若未手动重建，Viewer 仍可能查询旧位置/材质/光照；Viewer 重开或重置需要重新捕获。选中 Screen Probe 模式后，其 Compute Pass 仍随 Viewer 每次绘制重新构图和执行，尚未测量实际帧耗时。固定 8×8/8 rays 的 1080p 理论临时负载约 116.7 MiB，不含 Viewer 独立 GBuffer/深度、Cache Atlas 和 GPU 分配对齐；峰值与耗时尚未测量。编译和空场景启动不能证明 SDF 命中、Cache Lookup、Probe Integration 和颜色反弹正确。
- 建议：先在 `out/pro2` 复现/确认 GIViewer 崩溃，再用非空场景验证各阶段输出和间接漫反射；同时记录分辨率、GPU 时间、显存峰值和缓存重建耗时。完成测量后，再决定是否增加探针结果冻结/按需更新、场景修订跟踪与自动失效。保持 Viewer 与主渲染流程隔离，直到整条 Viewer 数据链有可复查的正确性验证，再讨论主流程接入。
- 验收：加载含互相照明的不同颜色静态网格，确认 Probe 命中和无缓存 miss 状态、Cache 辐射与接收材质一次乘法正确；手动重建、切换 Scene 后不读取旧缓存；用图像或读回确认颜色反弹并记录分辨率、时间和显存。
